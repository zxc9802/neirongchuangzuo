# 数字人前端对接

本次直接采用同事项目的后端，前端由本项目统一开发，保留现有蓝白风格，并参考 Oumomo 改为上方生成、下方懒加载素材与作品的布局。业务服务放在 `services/digital-human/`；上游接口根据源代码提交 `393d2eccd7d6e1b1d7423f40e1d7e97cef73b2cd` 核对。

本地网站使用 `http://127.0.0.1:5173`，数字人入口是 `/#avatar`，通过同源代理访问 `http://127.0.0.1:3001` 的后端。3001 自带的页面保留用于联调。新页面支持真实素材与任务接口；尚未配置模型凭据和公共媒体地址时禁用生成，不显示模拟成片。

## 页面流程

主流程是 **选择或上传人物口播视频 → 选择或上传声音 → 填写宣传文案 → 生成 → 预览与下载**。

形象素材是视频，图片仅用于封面。不要将“上传一张照片生成口播”设计成这个接口已有的能力。不选视频形象时，后端可仅生成配音。

页面包含形象库、音色管理、文案、后端支持的生成参数、进度与错误、历史记录、结果预览与下载，以及服务端标记为可恢复任务的恢复操作。未接入的背景替换、字幕排版等选项不展示为可用功能。

上方生成区收纳形象、声音、文案与可展开的参数；下方按“全部 / 视频形象 / 生成作品”显示卡片。接近底部时逐页加载，支持手动加载与失败重试。列表卡片按需加载封面，视频在打开预览时播放。

## 前后端放置方式

本站前端位于 `design/digital-human.js`、`design/digital-human.css`；接口适配层位于 `design/digital-human-api.js`。页面请求相对路径 `/api/...`，由 `preview.mjs` 转发给独立的 Next.js 数字人服务。代理同时处理素材和结果 `/jobs/...` 请求，并保留 Cookie、媒体 Range 请求及流式响应。

不要在 5173 页面里直接把请求地址改成 `http://127.0.0.1:3001/api/...`：现有账号接口校验请求来源，返回的媒体地址也按同源设计。本地设置 `AUTH_PUBLIC_URL=http://127.0.0.1:5173`、`AUTH_DESKTOP_URL=http://127.0.0.1:3001`；部署时应替换成真实访问来源。

根目录 `npm run dev` 通过 `scripts/dev.mjs` 一键启动工作台和数字人服务，或复用已运行的 3001 数字人服务。`npm run dev:design` 只启动工作台与代理，`npm run dev:digital-human` 单独启动后端。首次使用仍需安装数字人依赖并准备环境配置，详见根目录 README。

API 密钥只配置在服务端。前端只使用公开类型 `src/lib/public-contract.ts`，不要依赖内部供应商字段或服务器文件路径。

## 配置状态与生成门槛

新增 `GET /api/digital-human/status` 用于读取配置就绪状态。返回的布尔值只表示相关配置是否齐备，不会返回密钥，也不表示已经验证供应商账号、额度或生成效果。

页面根据状态提示缺少的服务配置；生成所需接口凭据和公共媒体访问条件不齐备时，禁用生成按钮。素材上传、形象库和音色库可在本地服务可用时真实使用并持久化。配置就绪后仍需执行一次真实出片验收，不能把状态接口当成供应商健康检查。

## 1. 登录与会话

进入工作台先请求 `GET /api/session`。有效会话返回 `{ success: true, data: { user, ... } }`；未登录返回 401。前端根据真实会话显示用户，不自行构造用户 ID 请求头。仅本机且未配置 SSO 的开发模式可使用开发身份；生产环境保留上游鉴权，不能把本地免登录当成上线方案。

独立账号模式的接口如下，均为同源请求，JSON 接口需设置 `Content-Type: application/json`：

| 操作 | 请求 | 请求体 |
| --- | --- | --- |
| 注册 | `POST /api/auth/register` | `{ "email": "you@example.com", "nickname": "店主", "password": "用户输入的密码" }` |
| 登录 | `POST /api/auth/login` | `{ "email": "you@example.com", "password": "用户输入的密码" }` |
| 退出 | `POST /api/auth/logout` | 无需业务字段 |
| 修改密码 | `POST /api/auth/password` | `{ "currentPassword": "原密码", "password": "新密码" }` |

注册与登录成功返回 `{ success: true }`，服务端写入会话 Cookie。独立账号模式需服务端启用并配置数据库；本地开发默认用户不能当成正式用户系统。

## 2. 上传并保存形象或音色

本站接口适配层按上游 `src/lib/client-media-upload.ts` 的协议处理对象存储直传与本地上传，取得 `{ uploadKey, storedRemotely }` 后认领素材。上游 React 页面仍使用 `uploadMediaFile(file, fileName, folder, onProgress)`。

上传目录及后端限制：

| `folder` | 支持的后缀 | 最大大小 |
| --- | --- | --- |
| `videos` | mp4、mov、mkv、webm、m4v | 500 MiB |
| `voices` | mp3、wav、m4a、aac、mp4、mov | 50 MiB |
| `thumbnails` | jpg、jpeg、png、webp | 10 MiB |

文件 MIME 类型也必须与目录对应。上传不是普通 `FormData` 接口：

1. `POST /api/upload/direct`，JSON 为 `{ folder, fileName, fileSize, contentType }`。
2. 返回 `direct: true` 时，按返回的 `parts: [{ url, size }]` 切片并 PUT 原始数据，再 `POST /api/upload/complete`，JSON 为 `{ uploadKey }`。
3. 返回 `direct: false` 时，`POST /api/upload?folder=videos&fileName=...`，请求体是原始 File/Blob，浏览器自动提供 `Content-Length`，不要手动设置它，也不要套 FormData。
4. 上传成功后立即用 `uploadKey` 创建形象或音色；凭证绑定当前用户，待认领有效期为一小时，只能认领一次。

保存视频形象：

```http
POST /api/avatars
Content-Type: application/json
```

```json
{
  "name": "老板口播形象",
  "uploadKey": "上传视频返回的 uploadKey",
  "coverKey": "上传封面返回的 uploadKey，可省略",
  "durationSeconds": 15,
  "width": 1080,
  "height": 1920,
  "fps": 30
}
```

返回 `{ success: true, avatar }`，后续任务只传 `avatar.id`。视频尺寸与时长可以用 `src/lib/client-video-preview.ts` 的 `inspectVideoFile()` 获取；没有封面时可复用 `recoverAvatarCover(id)` 请求服务端提取。上述数字仅为请求示例。

保存音色：`POST /api/voices`，JSON 为 `{ "name": "老板原声", "description": "音色说明，可省略", "uploadKey": "voices 目录上传返回的凭证" }`。返回 `{ success: true, voice, storedRemotely, extractedFromVideo }`。上传 MP4/MOV 音色素材时，后端提取音频。

| 素材管理 | 请求 | 响应或请求体 |
| --- | --- | --- |
| 形象列表 | `GET /api/avatars` | `{ success: true, avatars: [...] }` |
| 形象重命名 | `PATCH /api/avatars` | JSON `{ id, name }` |
| 删除形象 | `DELETE /api/avatars?id=...` | `{ success: true }` |
| 音色列表 | `GET /api/voices` | `{ success: true, voices: [...] }` |
| 删除音色 | `DELETE /api/voices?id=...` | `{ success: true }` |

用响应中的 `videoUrl`、`coverUrl`、`audioUrl` 播放或预览；根据 `canManage` 显示管理按钮。当前没有音色重命名接口，不要把仅修改本地名称当成保存成功。

### 展示区分页

本站展示区使用新增 `GET /api/digital-human/library`，前端适配方法为 `digitalHumanApi.listLibrary(options)`。原 `GET /api/avatars` 与 `GET /api/tasks` 保持完整列表行为，供原生制作台等调用。

| 查询参数 | 说明 |
| --- | --- |
| `kind` | `all` / `avatars` / `tasks`，默认 `all` |
| `limit` | 每页 1–48 条，默认 12 |
| `cursor` | 上次响应的 `nextCursor`；第一页省略，切换 `kind` 时丢弃旧游标 |
| `avatarId`、`taskId` | 可选，恢复选中的形象或任务；无需位于本页或当前分类中 |

响应没有 `success` 或 `data` 外壳：

```ts
type LibraryPage = {
  items: Array<
    | { kind: 'avatar'; id: string; createdAt: number; avatar: PublicAvatarItem }
    | { kind: 'task'; id: string; createdAt: number; task: PublicTaskItem }
  >;
  nextCursor: string | null;
  hasMore: boolean;
  total: number;
  counts: { all: number; avatars: number; tasks: number };
  selection: { avatar?: PublicAvatarItem; task?: PublicTaskItem };
  activeTasks: PublicTaskItem[];
};
```

`createdAt` 为毫秒时间戳；按时间倒序排列，同一时间依次按 ID、类型升序稳定排序。`total` 是当前分类的可见总数，`counts` 是各分类的可见总数，均不是当前页条数。游标由服务端生成并绑定分类，前端原样回传；参数或游标不合法时返回 400。

`selection` 只返回有权限访问的指定记录；`activeTasks` 返回当前用户可见的所有 `pending`、`processing` 任务，不受页码和分类影响，用于恢复进度。接口沿用原有形象、任务的权限及公开数据序列化，不暴露内部路径或未交付结果，响应禁止缓存。底层仍读取现有存储再筛选分页，未引入数据库分页或新的任务队列。

首屏请求第一页，接近列表底部再以 `nextCursor` 加载。切换分类、刷新或离开页面时应防止旧请求覆盖新列表；合并按类型和 ID 去重，错误时保留已有卡片并提供重试。当前选择与运行任务独立保存，不应因它们不在已加载页中而重置。

## 3. 创建生成任务

```http
POST /api/tasks
Content-Type: application/json
```

```json
{
  "avatarId": "选中的形象 ID",
  "speakerVoiceId": "选中的音色 ID",
  "scriptText": "欢迎来到我们店，今天为大家介绍本周活动……",
  "toneProfile": "low",
  "videoFit": "smart",
  "emotionIntensity": 0.8,
  "engine": "b"
}
```

参数约束：文案必填、最多 5000 字；`toneProfile` 为 `low` / `high`；`videoFit` 为 `smart` / `preserve`；`emotionIntensity` 在 0–1 之间。默认值分别是 `low`、`smart`、`0.8`。`engine` 公开值为 `a` / `b` / `c`，原页面默认 `b`，具体可用项应与服务端已配置的引擎一致。

省略 `avatarId` 表示只生成音频。省略 `speakerVoiceId` 会尝试默认音色，默认音色不存在仍会失败；页面上显式选中有效音色更清晰。

成功返回 `{ success: true, task }`，它只表示任务已受理，不代表成片完成。保存 `task.id`，提交期间禁用重复点击；不要因请求超时自动重复创建可能收费的任务。

## 4. 进度、结果与历史

`GET /api/tasks/{id}` 返回 `{ task }`。可以参考原页面在运行中每 1.2 秒轮询；组件卸载时清除定时器，网络失败显示可恢复的状态，不直接把任务判成失败。

也可以使用 `EventSource('/api/tasks/{id}/stream')`：每条 `message` 的 `event.data` 是 **task 本身**，没有 `{ task }` 外壳。服务端发送初始状态和更新、每 15 秒心跳，单次连接最长 5 分钟；完成或失败后关闭。前端在终态主动 `close()`，异常时可回退轮询。

| 字段 | 使用方式 |
| --- | --- |
| `status` | `pending`、`processing`、`completed`、`failed` |
| `step` | `idle`、`voice`、`prepare`、`check`、`render`、`finalize`、`done`、`error` |
| `progress` | 使用服务端进度显示进度条 |
| `logs` | 已处理过的用户可见日志，可按需展示 |
| `error` | 失败提示，不自行暴露内部报错 |
| `recoverable` | 为 true 时可显示“恢复任务” |
| `results.finalVideoUrl` | 成片预览地址，有值时再显示视频 |
| `results.exactAudioUrl` | 配音预览地址 |
| `results.audioFormat` | `wav` 或 `mp3`，用于选择下载接口 |

下载通过同源链接 `/api/tasks/{id}/download/final.mp4`；音频使用 `/api/tasks/{id}/download/voice-track.wav` 或 `voice-track.mp3`。不要从预览地址推测对象存储路径。后端只有在任务可交付时返回结果地址；外部积分用户还需结算完成。

原历史列表：`GET /api/tasks` 返回 `{ tasks: [...] }`，该接口没有分页参数；本站卡片展示区使用上文的 `/api/digital-human/library?kind=tasks` 分页。删除：`DELETE /api/tasks/{id}`，进行中或计费尚未确认时返回 409。恢复：`POST /api/tasks/{id}/recover`，无必填请求体，返回 `{ success: true, task }`；它用于取回已有对口型结果，不等于重新生成任意失败任务。

## 5. 错误处理

普通接口错误通常为 `{ error: "可显示的提示", code?: "错误码" }`。先检查 HTTP 状态，再解析结果：401 引导登录；403 检查来源或权限；400 展示参数错误；404 表示资源不存在或不可访问；409 表示上传凭证冲突或任务当前不可操作；402 可能为原积分体系余额不足；429 按 `Retry-After` 稍后重试；5xx 提示服务暂不可用。

不要给所有失败请求自动重试：创建任务和素材认领会改变状态。上传助手已有自己的限定重试逻辑，可直接复用。原积分字段不能当成我们平台已经完成收费接入。
