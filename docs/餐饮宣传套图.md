# 餐饮宣传套图

餐饮小红书的新任务默认选择“宣传套图”。自然美化、封面加字及旧任务的原有选择继续可用。上传、选方向、设置张数、生成的页面流程不增加步骤。

## 图像处理

1. 照片分析返回每道菜及餐具的 `foodSubjects`：归一化 `box`、`confidence` 和 8–24 点 `outline`，不可靠的定位可以留空。
2. 对可信菜品区域分别执行本地 U²-Net 显著性分割及 GrabCut 边缘细化。定位周围留出余量，避免粗略坐标截掉盘沿；保留主体连通区域、填充内部空洞，并在增补面积不超过15%时补齐凸轮廓。大块分离区域或不可靠边缘回退为完整实拍，多道菜保持原有相对位置。
3. 菜品 RGB 来自原图，处理只构造透明度和布局，不调用生图模型重绘菜品。最终缩放和 JPEG 编码会产生正常的采样、压缩差异。
4. 同一任务、同一方向使用统一配色，输出 1080×1440 的竖版图片，并根据最终图片顺序排版短句和序号。
5. 门头、环境、制作过程和人物使用完整实拍画面加边框；分割不可用、定位不可信或主体不完整时，也采用完整实拍画面，不因此判定照片不可用。
6. 文案和审核使用原始实拍证据，设计背景不作为真实装修、设施或消费场景的依据。

本版使用三组配色模板，不生成写实背景。复杂遮挡、贴边菜品、透明餐具和不可靠轮廓可能回退为完整照片排版。

## 接口兼容

`POST /api/restaurant/tasks/:id/generate` 的 `imageMode` 支持 `promotional`、`natural`、`cover`。接口省略此字段时仍按 `natural` 处理，以兼容已有调用方；网页新任务显式提交 `promotional`。

文案响应新增可选字段：

```json
{"imageCaptions":[{"imageId":"photo-1","text":"想吃肠粉就看看这一份"}]}
```

提供此字段时必须覆盖所有最终照片，ID 不重复，短句为 8–16 个汉字。首图使用 `coverText`，其余图片使用相应短句。短句和标题、正文一起进行事实与风险检查。旧响应不提供此字段仍可处理。

结果图片记录 `composition`，含处理版本、`source-cutout` 或 `original-frame`、原图哈希、配色及必要时的回退原因。这些信息用于后台排查，不增加用户操作。

## 运行环境

Docker 构建自动下载并校验模型，运行镜像沿用 `/opt/mix-venv`，无需配置远程抠图服务。模型约 176 MB，构建环境需要能访问 GitHub Releases。模型不写入 Git。

本地开发：

```powershell
python -m venv .data/restaurant-venv
.data/restaurant-venv/Scripts/python.exe -m pip install "numpy>=1.26,<3" "onnxruntime>=1.20,<2" "Pillow>=11,<13" "opencv-python-headless>=4.11,<5"
npm run setup:restaurant
```

在忽略提交的 `.env.local` 中设置 `RESTAURANT_PYTHON_BIN` 为上述虚拟环境 Python 的绝对路径，然后重启本地服务。自带模型时可设置 `RESTAURANT_SUBJECT_MODEL_PATH`。

模型来源：[U²-Net](https://github.com/xuebinqin/U-2-Net)，下载使用 [rembg 发布的 u2net.onnx](https://github.com/danielgatis/rembg/releases/download/v0.0.0/u2net.onnx)。安装脚本验证大小 `175997641` 字节、MD5 `60024c5c889badc19c04ad937298a77b`，使用临时文件及原子替换，防止残缺权重投入运行。

分割进程串行处理，最多排队 16 次，每张超时 45 秒，空闲 30 秒退出释放内存。不可用时回退为完整照片排版，正式积分仍按成功交付的成品张数结算。原图、结果与 ZIP 保留三天，文字记录三十天。

## 校验

`npm run check` 校验新增 JavaScript 模块；`npm run test:restaurant` 覆盖源像素保护、多菜品、轮廓保护、失败回退、安全裁剪、短句审核、统一配色、完整发布包和积分结算。真实照片效果仍需结合成品人工检查。
