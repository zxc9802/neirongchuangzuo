# Agent 与 AI 图片模型接入

日期：2026-09-28。此文记录本轮实际接入情况；早期产品设计及数字人验收报告保留历史状态，不作为当前 Agent、AI 图片是否接通的判断依据。

## 当前能力

| 功能 | 实现情况 |
|---|---|
| Agent 对话 | 通过 OpenLux `/v1/chat/completions` 调用 `gpt-6-luna`，支持多轮文字与用户消息中的参考图片 |
| AI 图片 | 通过 OpenLux `/v1/images/edits` 调用 `gpt-image-2.5-sunburst-c`，至少一张原图，默认每次请求一张 PNG 图片 |
| 图片结果 | 显示真实任务状态，成品持久化保存，支持查询、预览与下载 |
| 暂未接入 | 纯文生图、网址导入、PDF / Word 等文档上传分析；AI 视频和 AI 混剪的模型生成 |
| 数字人 | 沿用独立服务与既有接口；本轮配置不代表其配音、对口型或成片链路已验证 |

当前 Agent 用于分析用户输入、图片和整理宣传文案，不会代替用户发布内容或自动调用图片生成。行业宣传表单原有的固定方案仍按行业模板整理，不把模板输出标成模型回复。

## 配置与启动

1. 在仓库根目录将 `.env.example` 复制为 `.env.local`，填写自己的 `OPENLUX_API_KEY`。已有配置时不要覆盖。
2. 使用默认 `OPENLUX_CHAT_MODEL=gpt-6-luna` 和 `OPENLUX_IMAGE_MODEL=gpt-image-2.5-sunburst-c`；服务端读取环境变量或根目录 `.env.local`，环境变量优先。
3. 执行 `npm run dev:design` 启动工作台与 Agent / 图片服务；需要同时启动数字人服务时使用 `npm run dev`。
4. 打开 `http://127.0.0.1:5173/`，从导航进入 Agent 对话或 AI 图片。更改配置后重启工作台。

密钥只在服务端使用。根目录 `.env.local` 与 `.data/` 已被 Git 忽略；状态接口不返回密钥，浏览器也不直接请求 OpenLux。当前根目录的模型配置与数字人子项目配置独立，不能混淆两个 `.env.local` 的用途。

## 输入与结果边界

AI 图片仅支持有效的 PNG、JPEG、WebP 原图，单张最多 8MB，最多 9 张，原图合计最多 24MB。创作要求为 1–1000 字。界面比例为 1:1、3:4、4:3、9:16、16:9；画质支持自动、低、中、高。服务端以 multipart 发送 `model`、`prompt`、重复的 `image`、`n=1`、`size`、`quality`、`format=png` 和 `response_format=b64_json`，也兼容供应商以图片 URL 返回结果。

请求尺寸是发送给供应商的偏好，不保证成品像素完全一致。本轮 3:4、低画质测试请求了 960×1280，实际返回 1086×1448；不得把界面比例或请求参数展示成固定像素承诺。

Agent 每次最多发送最近 20 条消息，文字总量最多 32000 字；最多携带 4 张参考图，总大小最多 24MB，单张图片仍限制为 8MB。参考图只允许附在用户消息中。已验证真实文字回复，以及车间和火锅图片识别；这些样本通过不代表所有图片或复杂资料的理解效果。

## 本站接口

这些是本机工作台的同源接口，不是供应商直连地址。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/ai/status` | 返回模型名、配置是否存在与输入限制，不验证余额或实时可用性 |
| `POST /api/ai/chat` | 带 UUID `requestId` 提交消息；重复提交同一内容只返回原任务 |
| `GET /api/ai/chat/:id` | 查询原回答：处理中 202、完成 200、原失败 502、到期 410 |
| `GET /api/ai/usage` | 查询全站每日额度、近期调用状态和清理状态，不返回密钥或正文 |
| `POST /api/ai/images` | 提交原图编辑任务，接收 `requestId`、`prompt`、`images`、`ratio`、`quality` |
| `GET /api/ai/images` | 读取最近的图片任务 |
| `GET /api/ai/images/:id` | 读取单个任务和结果 |
| `GET /api/ai/media/:id/:filename` | 读取已完成任务的图片；加 `?download=1` 下载 |
| `HEAD /api/ai/media/:id/:filename` | 检查图片类型和长度，不返回图片正文 |

任务依次进入 `queued`、`running`，最终为 `completed` 或 `failed`。相同 `requestId` 与相同请求内容返回原任务，不重复产生模型调用；同标识但不同内容会拒绝。服务一次只执行一个图片任务；同一数据目录由独占运行锁限制为一个实例，第二实例拒绝启动。

模型请求不会自动重试。服务重启时，未完成任务会标为中断失败，不会重新提交；上游可能已经执行，应先核对供应商记录，再决定是否新建任务。错误内容使用本站提示，不把供应商响应正文或密钥直接交给前端。

## 数据保存

| 数据 | 保存位置与期限边界 |
|---|---|
| 图片原图、Agent 参考图 | 当前页面内存及提交请求；本站服务不将原图持久化保存，刷新后需重新选择 |
| 图片生成任务和成品 | 根目录 `.data/ai/<任务ID>/`，包含任务记录与结果图片，重启后可重新读取 |
| Agent 文字历史 | 当前浏览器 localStorage，不是服务器端跨设备历史 |
| 商家资料、草稿、参数与收藏 | 沿用当前浏览器 localStorage |

图片成品和可查询的对话答案自完成起保留 72 小时；到期禁止读取并删除生成文件与答案，失败任务的半成品立即清理。服务启动即执行清理，随后定时重试，状态可通过 `/api/ai/usage` 查看。最小调用账本和任务去重记录长期保留，不保存原图或聊天请求正文；旧图片任务仍保留创作要求。本站不保存原图不等于供应商不处理或保留输入，供应商的数据政策需要单独核对。

## 部署前仍需完成

当前服务仅绑定 localhost，按单实例开发使用；Agent 与图片接口没有用户登录、用户归属和多人数据隔离。上线到公司现有服务器前，应接入现有账号与权限体系，为任务和图片增加用户或商家归属，按部署方案接入持久化任务队列、对象存储，并与公司计费规则衔接。现有全站 20/100 每日调用上限、每分钟 10 次、单实例锁和持久化去重可用于受控试用；它们不是多人账户额度或金额计费。必须让业务权限覆盖任务查询、结果读取和下载，不能只隐藏页面入口。

同一服务器可以运行现有数字人、混剪与新的 Agent / 图片服务，但共用服务器不等于共用登录或数据权限。本轮未部署，也未将本机模型接口开放到公网。
