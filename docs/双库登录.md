# 店 AI 双库登录

工作台使用独立登录和注册入口 `/login`、`/register`。根目录与数字人服务均设置 `AUTH_MODE=standalone`，主站会验证数字人账号服务的会话。

登录和注册均支持普通账号，不要求 `@`；已有邮箱形式的账号仍可使用。注册只填写账号和密码，昵称默认取账号。账号去除首尾空格并统一为小写，不能包含空白或控制字符，最长 254 个字符；新密码仍需 10–128 个字符。为兼容既有数据，账号继续存储在原有 `email` 文本列，接口兼容旧客户端的 `email` 字段。

## 数据库配置

在数字人服务的服务端环境变量中设置：

```dotenv
AUTH_MODE=standalone
AUTH_DATABASE_URL=新网站数据库的PostgreSQL连接串
INTERNAL_AUTH_DATABASE_URL=原内部账号数据库的PostgreSQL连接串
AUTH_PUBLIC_URL=https://网站域名
```

本地配置使用 `services/digital-human/.env.local`；根目录 `.env.local` 也设置 `AUTH_MODE=standalone`。同一个部署进程启动两项服务时，共享服务端环境变量。连接串不得放进前端、版本库或日志。`AUTH_DESKTOP_URL` 仅在确实需要另一登录来源时填写。

- 新注册用户、会话、限流记录只写入 `AUTH_DATABASE_URL` 的 `digital_human_auth` schema，首次使用自动建表。
- 旧库使用只读连接，只查询 `public.users`。仅 `billing_audience=internal`、`account_status=active`、`is_verified=true` 的用户可通过原 bcrypt 密码登录。
- 内部账号不会复制为新库注册用户，其本站会话单独写入新库 `internal_sessions`。会话读取时重新核验旧库账号状态、密码指纹和 `auth_token_version`；失效会话不会在重新启用账号后复活。
- 已存在的内部账号不能在本站再次注册。旧库外部账号可另行注册本站账号，但原密码不会授予本站访问权限。两库同名账号不自动合并，已有本站账号优先。
- 内部账号密码在原系统修改；旧库的管理员角色、积分不会迁移成本网站管理权限或余额。
- 新库故障时停止账号操作；旧库故障时内部账号验证和需要检查重名的注册停止，已有本站账号仍可登录。

## 网站行为

未登录访问主页会进入登录页；AI 接口返回 401。账号服务故障返回 503。数字人接口继续使用已有账号归属验证。AI 图片、任务、成品下载和对话结果新增账号归属；历史无归属的本地任务不会分配给任意注册用户。

浏览器中的文案、商家资料、对话、收藏及数字人草稿按账号分开保存；原有未登录预览数据保留。左侧“我的账号”可查看当前账号和退出。

每日模型调用上限仍为全站共用。本次不增加积分扣费、邮箱验证邮件或密码找回，也不代替生产部署适配。数字人生成仍需配置模型、媒体存储和运行依赖。

## 验证

运行 `npm test`、`npm run check`、`npm run check:digital-human` 和 `npm run test:digital-human`。数字人 PostgreSQL 集成测试需通过服务端 `TEST_DATABASE_URL` 指向可创建临时数据库的测试实例；测试创建随机命名的独立数据库并清理，只使用构造的账号，不修改原内部用户。

重点覆盖内部/外部账号边界、注册写入位置、旧密码兼容、改密/停用撤销、退出、数据库故障和跨账号作品访问。
