# AI 视频 · 人物 1:1 复刻

输入一段单个人物的视频，再输入一张目标人物照片和声音参考，由视频模型替换人物、Chatterbox 转换原视频音色。页面可切换「qiya-2.0 / qiya-2.5 / qiya-2.0-f1 / qiya-20-m1 / Wan 3.0」。供应商模型 ID 保留在请求协议和技术文档中。固定提示词明确人物外貌、发型和服装均采用照片，去掉原人物与照片不一致的服饰、配饰和衣服文字，替换贯穿全片。保留原视频的动作、表情、说话节奏和镜头运动，以及人物以外的场景、商品、背景标识和已有字幕；不新增动作、重复片段或延伸表演。这些是生成目标，不是逐帧一致保证。

四个 qiya 版本和 Wan 3.0 共用上述替换指令。提示词开头将人物替换与原视频去水印并列为两项编辑，明确删除抖音/TikTok 等平台图标、平台名称、账号 ID、@用户名、作者昵称及相邻角标，不能将这些叠加水印当成台词字幕或场景标识保留。固定或移动的文字、图案水印均要求全片去除并自然修复遮挡区域，不保留、复制或新增水印，不以模糊、马赛克、色块或裁切遮盖。去水印要求优先于背景、字幕和口型保留要求，正常台词字幕、商品包装文字和真实招牌仍保留。Chatterbox 模式额外要求保留原视频嘴唇动作与时间，并同时完成去水印，不再限定“只将人物外观替换”；转写用于检查换声台词。历史 IndexTTS2 独立配音任务保留原有配音与口型流程。

这些指令不能保证模型清除原片水印。原版复刻没有独立的水印擦除后处理；深度复刻增加了下文说明的 STD 全屏清理。“复刻完成”表示任务处理完成，不代表已经通过逐帧无水印验收。更新不会修改已经完成的历史成片。

## 使用

### 深度复刻模式

在「1:1 复刻」内切换「原版复刻 / 深度复刻」。原版保留原来的必填人物照片、声音参考和生成流程。两个模式在当前页面会话中分别保留所选素材、版本和任务，切换不会修改或取消已提交的任务；历史深度复刻记录会恢复对应模式和替换项目。

深度复刻支持全部五个在用版本：qiya-2.0、qiya-2.5、qiya-2.0-f1、qiya-20-m1、qiya-3.0。参考视频必填，人脸、声音、商品、背景四项默认关闭，可以自由组合；仅开启的项目需要对应参考素材。商品与背景分别上传 JPG / PNG / WebP 图片，最大 10 MB、宽高至少 300 像素。未开启的画面项目通过独立提示词明确保留；未开启声音时，关闭模型输出音频，再将原视频音轨合回成片，无音轨原片仍保持静音。开启声音的新任务先用 SAM Audio 分离人声与背景声，只将人声交给 Chatterbox 转换音色，再把分离的背景声混回成片，不依赖是否替换人脸。

人声分离使用现有 fal 密钥调用 `fal-ai/sam-audio/separate`，提示词为 `Human speech`，WAV 输出、单候选；`target` 用作换声输入，`residual` 保存为背景声。原音轨以 48 kHz 双声道提取，保留开头静音；混音保持背景声的时间轴和声道，不对整条音轨变速，末尾按成片时长补静音或截断，并限制混音峰值。AI 分离可能损伤音乐或留下原人声，需试听验收。页面显示分离与混音进度，成片提示核对音乐、人声残留与口型。

分离与换声的任务编号分别持久化，网络中断和重启继续查询原任务，下载失败只重新保存结果；分离失败不退回整轨换声，提交结果不确定时不重复发送收费请求。已开始旧换声流程的记录继续使用原任务，不补做分离或重新收费。新增上游分离调用沿用原计费通道：固定模型价格保持不变，API 实际费用模式按 fal 用量记录并核对分离与换声两笔调用。分离素材随任务到期清理。接口与供应商报价见 [SAM Audio API](https://fal.ai/models/fal-ai/sam-audio/separate/api) 和 [价格页面](https://fal.ai/models/fal-ai/sam-audio/separate)。

创建请求使用 `mode: "deep"` 和 `replacements: { photo, voice, product, background }` 布尔开关；未传模式的请求沿用原版。`POST /tasks/:id/options` 仅允许修改深度复刻草稿，关闭项目会移除其任务素材引用，提交后锁定。商品与背景使用 `PUT /tasks/:id/product`、`PUT /tasks/:id/background` 上传，并沿用任务所有权、签名访问及到期清理。开始生成前校验所有开启项目，缺失素材时不预留积分。历史停用模型不新增入口。

Seedance 各版本使用同一多图编辑请求，按「人脸、商品、背景」中实际开启的顺序编号，不传未选图片；qiya-3.0 将这些图片分别映射到 `reference_image`，独立编号为「图1、图2、图3」。[万相 3.0 API 文档](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)支持多参考图，图片和视频分别计数。各版本继续按原本单段上限处理最长 60 秒视频，每段复用相同替换素材，拼接后只合成一次完整声音。

验证覆盖五个模型的全部 16 种开关组合、上传与缺素材校验、素材访问控制、重启后继续原任务、60 秒分段，以及真实 FFmpeg 音轨恢复和静音原片。供应商请求使用模拟响应测试，未进行付费生成验收；人物、商品文字、握持遮挡与背景一致性仍需用真实素材预览验收。

### 原版复刻

1. 打开「AI 视频 → 人物 1:1 复刻」，选择含原声的参考视频、目标人物照片和声音参考。
2. 点击「一键生成」。服务端识别原视频语音，使用 Chatterbox 将整段原声转换为上传音色，核对台词和时长后提交换人。画面生成关闭音频，最终合成转换后的声音，不逐句变速。
3. 素材审核、生成、保存与结算状态会自动更新；可离开页面，再从最近记录查看。
4. 成片可播放和下载，也会出现在「资产 → 视频」。成片保留 3 天。

刷新页面后默认显示空白的新建复刻表单，声音固定使用 Chatterbox 音色转换；点击「最近的复刻」中的记录才打开对应素材、生成进度或成片。旧草稿从页面重新提交时也使用音色转换，刷新不取消后台生成任务。

### 生成版本

- **qiya-2.0**（默认）：Seedance 2.0，模型 ID `doubao-seedance-2-0-260128`，单段最多 15 秒，整条最多 60 秒，1 元/秒（125 积分/秒）。
- **qiya-2.5**：Seedance 2.5，模型 ID `doubao-seedance-2-5-260628`，单段最多 30 秒，整条最多 60 秒，1.5 元/秒（187.5 积分/秒）。
- **qiya-2.0-f1**：Seedance 2.0 fast，模型 ID `doubao-seedance-2-0-fast-260128`，单段最多 15 秒，整条最多 60 秒，0.8 元/秒（100 积分/秒）。
- **qiya-20-m1**：Seedance 2.0 mini，模型 ID `doubao-seedance-2-0-mini-260615`，单段最多 15 秒，整条最多 60 秒，0.5 元/秒（62.5 积分/秒）。显示名称按价格表原文保留。

四版沿用同一 API 地址、项目和密钥，生成请求仅更换 `modelId`，人物替换参数与配音流程共用。依据[参考项目模型配置](https://github.com/zxc9802/seedance/blob/main/src/modelConfig.js)，2.0 与 fast 的生成档位为 4/5/6/8/10/12/15 秒，2.5 另支持 20/25/30 秒；mini 的完整 ID 及 15 秒上限参照 [Mini 视频编辑接口文档](https://doc.dmxapi.cn/doubao-seedance-2-0-mini-260615-video-editing.html)，沿用 2.0 的时长档位。系统按参考视频时长选择档位。参考视频自动识别实际时长，所有在用版本支持完整的 2–60 秒素材，超过本模型单次上限时自动分段；不截取开头、不静默丢弃后续内容，超过 60 秒会明确提示更换素材，参考视频文件均限 300 MB；声音参考仍限 2–15 秒、15 MB。模型配置和模拟请求测试不代表已验证当前上游账号的真实生成权限。

上传前及未提交的草稿可切换版本；切换后根据完整原片时长和所选模型上限重新计算分段方案与预估费用，不需要用户选择生成秒数；历史版本不增加长视频入口。生成提交后版本锁定，恢复任务与查看记录均保留该版本。`api_cost` 模式下，qiya 草稿预估、余额检查、费用预留和视频结算按上述 2026-10-20 价格表计算，提交时保存单价；未带单价快照的已提交旧任务仍按原 1 元/秒结算。历史 IndexTTS2 配音和口型不额外加收，Chatterbox 换声按实际回执另计；历史固定积分模式保持原规则。

300 MB 是工作台接收完整原片的上限。2026-10-23 核对官方文档：[Seedance 2.5 / 2.0 系列](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)单个参考视频不超过 200 MB，[万相 3.0](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)不超过 100 MB；Seedance 中转素材服务的实际大小限制尚未实测。

上传后沿用尺寸适配与按时长分段，在提交模型素材前检查每个实际输入文件的大小。Seedance 按 200,000,000 字节、万相标准版与极速版按 100,000,000 字节判断；低于或恰好达到上限不进行额外压缩，仅超限文件通过 FFmpeg 两遍编码生成独立参考副本，目标分别为 180 MB、90 MB。保持分辨率、帧时间、画幅和完整时长，音轨存在时保留；重新验证大小、尺寸、时长、音轨并完整解码后才提交。大小处理不覆盖原片，换声和原声恢复仍使用原片。压缩失败暂停/停止视频生成，不自动提交或切换供应商；已经发生的配音等调用仍按原计费规则核对。副本随任务保存、恢复与到期清理，模型素材服务和万相备用上传都使用经过检查的副本。此处理不改变生成分辨率或成片编码参数；参考片段压缩可能影响小字、人脸和纹理细节。

### 全部在用 qiya 版本自动识别时长与分段（最长 60 秒）

qiya-2.0、qiya-2.5、qiya-2.0-f1、qiya-20-m1 和 qiya-3.0 自动处理上传视频的完整时长，不再显示时长勾选框或秒数输入框。单次上限：2.5 为 30 秒，其余为 15 秒。

上传后由服务端探测素材实际时长（包含小数秒）。在单次上限内一次生成；超过时按该版本上限拆段，再按原时间线拼回完整的一条。2.5 最多两段、每段 4–30 秒；其他在用版本最多四段、每段 4–15 秒。比如 39 秒的 qiya-3.0 复刻需要三次视频生成，60 秒需要四次；整条原声只换声一次。

- **完整素材与兼容**：`POST /tasks` 不再读取旧客户端的 `targetDuration`，`POST /tasks/:id/duration` 返回 `410 VIDEO_DURATION_SELECTION_REMOVED` 提示刷新。旧草稿的截取设置在重启加载、换模型、上传或开始生成时清除；已提交任务沿用已有素材与分段记录。上传和开始生成均核验整条 2–60 秒范围，超限不会按旧设置截取，且不预留积分、不提交生成。镜头检测、换声、字幕检查、切段及结算均使用完整原片；恰好达到单次上限不分段，超过一帧也会分段。
- **接缝位置**：上传时检测镜头硬切（FFmpeg `scene` 分数大于 0.4）和原声停顿（VAD 人声区间之间至少 0.25 秒的空隙），每次接缝候选窗口保证当前段至少 4 秒、不超过模型上限，且剩余内容能放入后续各段。优先镜头切换处；窗口内没有切换时选说话停顿，取停顿中点（超出窗口时收回窗口边缘）；都没有时按档位边界切分。同类候选先比当前段与剩余段的档位总和，补齐秒数最少者优先，其次停顿更长、更靠近中间者优先。接缝对齐到原视频帧。候选数据只在服务端保存，两段任务显示接缝秒数和原因，多段任务显示总段数。
- **声音**：超过当前模型单次上限时只能使用 Chatterbox 整条换声；选择其他声音流程时 `/start` 返回 `VIDEO_VOICE_ENGINE_INVALID`，不预留积分。整条原声只转换一次，各段画面均关闭音频生成，拼接后合成同一条转换声音，避免各段音色或语气断开。
- **生成与拼接**：每段从原片切出（`segment-N.mp4`），作为独立素材审核，按本段实际时长写入时长提示词并选档位。各段结果分别下载为 `segment-N-result.mp4`，后续各段统一到第一段成片的尺寸和帧率（不同时等比缩放并补黑边），每段按其在原片中的区间裁短或末帧补齐，再无音轨拼接为 `generated.mp4`，最终合成换声音轨。成片时长等于完整参考视频时长。
- **计费**：Seedance 预留各段档位之和（例如 45 秒原片切成 21.03 + 23.97 秒，各按 25 秒档位，共预留 50 秒）；完成后按实际交付时长结算，不超过预留，档位补齐的秒数不收费。`api_cost` 模式按各段档位之和记录 Seedance 回执。Wan 逐段保存实际输入与输出用量，合并核对费用；任一用量缺失时继续查询原任务，不按零费用结算。
- **恢复**：每段在调用付费接口前单独落盘提交边界。重启时如果所有已发出的段都已拿到任务编号，只继续提交尚未发出的段；任何一段已发出但没有任务编号时，按现有规则等待核对，不自动重发。某段被上游明确拒绝（权限、余额、IP）时等待账户恢复，继续处理只提交被拒绝及尚未提交的段，已确认的段不重复付费。任一段生成失败按整条任务失败处理，不自动重新生成。
- 页面显示分段数、接缝位置与原因、各段提交/完成进度，以及「正在保存并拼接分段成片」状态；下载进度标明第几段。

接缝处的人物、动作和光线连续性取决于模型，各段分别生成可能在接缝处出现跳变，需预览成片。该流程已有模拟接口测试和真实 FFmpeg 切段/拼接测试，自动时长、边界分段和旧草稿迁移已有模拟接口测试，尚未用真实 60 秒素材付费生成验收，Chatterbox 对 60 秒原声的转换效果也未实测。实现见 `services/video/segments.mjs`（切段规划、镜头检测、切段与拼接）和 `services/video/server.mjs`（任务流程）。

### Wan 3.0 首发路由、快速版与 Chatterbox

普通版模型为 `wan3.0-video`；选择 qiya-3.0（Wan 3.0）后，可勾选旁边的「快速版」，使用 `wan3.0-video-prime`。原版复刻和深度复刻均支持，草稿保存所选模型，提交后锁定。快速版预估、预留和实际结算均按 738 积分/秒，普通版为 492 积分/秒，增加 50%；沿用按成片时长结算、总积分四舍五入规则。

新任务优先复用 Seedance 的 `VIDEO_*` / `MATERIAL_*` 上游配置，调用 `/openApi/generate`、`/openApi/queryResult`。首发不注册素材 ID，也不再让上游下载工作台的 `/source/…/photo` 等地址：所选人物、商品、背景图片和对应视频片段先上传至现有 COS 私有存储，再传入 HTTPS 临时签名直链；旧流程需要参考声音时也使用同样的上传方式。复用 `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_BUCKET`、`COS_REGION`，图片为 JPEG，视频沿用现有压缩规则。临时对象位于 `workspace-video/wan3/<任务编号>/`，与永久素材库分开；任务到期时删除这些临时对象。

上传完成记录随任务保存，重试和重启复用对象，每次提交前重新签发有效期 3 天的链接，避免长时间排队使用过期链接。COS 上传或签名失败时不会提交生成，也不消耗首发失败预算；缺少配置时暂停并提示管理员。已排队但未提交的旧任务自动改用 COS，已有生成编号的任务仍只查询原回执。

每段首次明确生成失败后重试 3 次（共 4 次），仍失败则切换阿里云官方接口；官方请求保留普通版或快速版的模型 ID，并单独上传官方 OSS 素材。失败回执、重试次数和当前路由持久化；已完成片段不重新生成。生成提交发生超时、断连、5xx 或缺失任务编号时，不能确认是否已创建付费任务，不盲目重试或切换；有编号的任务只向原路由查询，直到确认成功或失败。

官方备用接口为北京地域 `https://dashscope.aliyuncs.com`，使用服务端 `DASHSCOPE_API_KEY`，按需上传 DashScope 临时 OSS 素材。只有官方配置时仍直接走官方；升级前已提交的任务继续原官方路由。本地开发从 `.env.local` 读取；生产部署需配置同名环境变量。声音转换继续使用现有 `FAL_KEY` / `FAL_API_KEY` / `VIDEO_FAL_KEY`。

本站所有用户的 Wan 生成共用持久化队列，按通道分别计算在途名额：首发通道最多 600 个，官方兜底仍为 5 个；普通版与快速版共享对应通道的额度。两条通道合计仍保持任意滚动 1 秒最多提交 5 次创建请求，本次只提高首发并发，不提高每秒提交次数。各通道按入队顺序提交，官方队列排满或限流等待不会挡住首发通道。长视频每个片段各占一个名额，已完成片段立即释放名额，不等待整条视频拼接；失败片段切换官方后计入官方额度。页面显示「排队等待生成」、下一待生成片段在所属通道的排队位置和分段进度。重启保留在途计数，停止本地任务不释放仍在上游运行或结果不明的名额。排队不消耗原有 30 分钟自动处理时限，可以停止尚未提交的任务。

队列顺序、提交边界、请求时间和上游任务编号随 `task.json` 保存，复用视频服务的持久化单实例写锁；重启继续原队列，不重复提交已确认或结果不明的调用。已提交的任务即使用户停止或其他片段失败，仍查询至上游终态才释放名额；提交结果不明且无任务编号时保留名额等待核对，不按超时猜测完成。HTTP 429 明确未创建任务时释放名额，遵守 `Retry-After`（未提供时等待 5 秒）后自动重试；网络断开等不确定情况不自动重发。此队列覆盖本部署的复刻入口，同一阿里云账号在其他应用中的调用仍共享官方额度，遇到上游限流会继续排队。换声顺序、模型参数与其他生成版本保持原流程。

官方 API 的参考视频输入单段最多 15 秒，且输入与输出时长之和不超过 30 秒；因此等时长人物复刻每次最多处理 15 秒，不能直接按宣传的 30 秒输出上限上传 30 秒原片。依据：[万相 3.0 API 参考](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)（2026-10-22 核对）。本系统参考视频支持 2–60 秒、300 MB，自动识别完整时长并按最多 15 秒拆段。输出固定 720P；上传照片和对应原视频片段，沿用共用复刻提示词，参数为 `ratio=adaptive`、`duration=-1`、`prompt_extend=false`、`watermark=false`。Chatterbox 使用原视频音轨和用户声音参考，Wan 请求不传参考声音且设置 `audio=false`；最终只合成已转换的声音。音色转换与原声时长相差超过 0.25 秒时暂停，不强行变速；口型与音色仍需预览验收。`watermark=false` 本身不会清除原素材已有水印；去除原素材水印由共用提示词明确要求，实际效果仍需成片核对。

新任务使用上面的固定模型积分价格，不因重试或切换路由重复预留。历史 `api_cost` 任务继续按原官方回执核对：换人按接口返回的输入＋输出实际用量乘提交单价结算，720P 原价 0.6 元/秒，2026-08-24 至 2026-10-31（北京时间）按公布的 7 折单价 0.42 元/秒，11 月 1 日自动恢复原价；免费额度及账户专属优惠不在接口用量中体现。Prime 官方 720P 费用为 0.9 元/秒，不套用普通版限时折扣；此供应商成本不改变快速版对用户加收 50% 的固定积分价格。历史 Chatterbox 和语音识别分别按已有 fal 回执结算。历史成本计费任务缺少 Wan 用量时保留待核对状态，不把输入时长漏计或按零费用交付。上传回执、生成任务编号、声音回执与用量落盘，刷新和重启只查询已有任务；提交结果不明时不自动再次付费生成。

官方文档：[Wan 3.0 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)、[计费](https://help.aliyun.com/zh/model-studio/model-pricing)、[7 折延期说明](https://www.aliyun.com/product/bailian)。

Wan 2.2 已从页面和新任务模型列表下架，创建任务、切换模型和显式提交该模型均会拒绝。已提交任务保留原模型的结果查询、成片下载及费用结算；旧草稿可改用现有生成版本。

### 声音参考

必须上传清晰的单人 MP3 / WAV，2–15 秒、最大 15 MB，指定目标音色。沿用原视频台词、开口时间和停顿，不使用参考音频里的台词。「无原声直配（试用）」固定从原视频语音转写台词，不检查或提取画面字幕。历史模式仍按已保存流程处理。

原声转文稿使用 fal.ai 的 `fal-ai/elevenlabs/speech-to-text/scribe-v2`，复用 `FAL_KEY` / `FAL_API_KEY` / `VIDEO_FAL_KEY`，不再读取复刻原先的 `VIDEO_TRANSCRIPTION_*`、`MOTION_*` 或 302 语音识别配置。识别保留词级时间戳，关闭说话人区分和非语音事件标注，不启用加价热词。请求编号与结果按音频内容持久化，查询暂时失败或重启后继续查询原任务；提交结果不确定时不自动重发。语音转写文稿已保存时复用；试用模式不会复用旧字幕台词，其他模式仍可使用已识别的字幕。正式生成按现有任务计费范围核对识别费用，草稿分析保持原有不单独向用户计费的行为。

新建复刻固定采用「无原声直配（试用）」，由 Seedance 同时生成视频和声音；前端不显示该模式卡片。页面提交固定使用 `sourceAudioMode=silent`、`voiceEngine=seedance`，包括重新打开的旧草稿。创建接口省略声音参数时也默认这组值；显式旧接口参数保留兼容，已提交任务继续按原记录处理。

Seedance 直接生成视频与声音：原视频语音先转写，提交的视频移除音轨，上传声音以 `referAudioUrl` 传入，提示词要求跟随参考音色。参考声音可在现有 2–15 秒范围内使用更长、清晰的单人录音，但长度本身不能保证音色准确。该路线不调用 IndexTTS2 或额外的口型服务。

四个 Seedance 生成版本仅提供以下声音流程，原声参考和独立配音的选择入口已删除：

- 「无原声直配（试用）」：`sourceAudioMode=silent`、`voiceEngine=seedance`，必须上传声音参考，原片必须包含原声。固定先将原片语音转为台词和时间线，不运行字幕检测、OCR 或字幕回填，再向 Seedance 提交无音轨视频和上传声音；开启音频生成，上传声音通过 `referAudioUrl` 作为唯一音色参考。提示词明确画面字幕可能不完整，配音只依据原声转写，不得据字幕增删台词。已用字幕分析过的草稿进入该模式时清除字幕结果，重新从原声转写；保存的语音转写可在重启后复用。转写未完成时等待或重试，不回退到字幕，也不提前提交视频生成。缺少原声音轨时在预留费用前保存进度，等待更换原片。直接生成画面和配音，不调用独立 TTS 或口型模型。情绪只能参考画面表演及台词语义，不具备原声语调和气口的参考；音色、情绪和口型需实际试听，提示词不能保证百分之百复刻。[完整提示词示例](无原声直配提示词.md)。

去音轨使用 FFmpeg 视频流直拷贝生成 `source-silent.mp4`，删除全部音轨，素材签名地址只提供无音轨副本。原片仍可在用户页面预览。去音轨失败时不向模型提交、不回退到带原声视频；新直配任务沿用进度保存和退避重试，反复未完成时等待继续，页面不展示上游技术报错；视频提交结果不确定时不重复付费生成。独立配音的 5 秒情绪参考检查不用于直配模式，直配视频仍受所选版本原有时长限制。

### 历史独立配音流程

选择 IndexTTS2 时必须上传声音参考：新任务通过 fal.ai 的 `fal-ai/index-tts-2/text-to-speech` 合成，提交地址为 `https://queue.fal.run/fal-ai/index-tts-2/text-to-speech`（[官方接口文档](https://fal.ai/models/fal-ai/index-tts-2/text-to-speech/api)）。上传声音仅作为 `audio_url` 音色参考；相邻短句按同一说话人合并，通常以 6–10 秒为目标，末尾不足 5 秒时尽量并入上一组；围绕该组的原位置扩展截取原视频音频，分别作为 `emotional_audio_url`，情绪强度 `strength=0.8`，关闭从台词推断情绪。台词写入 `prompt`。最多同时合成三段，与 Seedance 人物替换并行处理。各段去掉首尾多余静音，再按原区间调整语速，保留区间之间的静音。IndexTTS2 提供独立音色和情绪参考，但听感、情绪还原程度仍需真实成片试听。

IndexTTS2 两路完成后，以同一条完整配音音轨和 Seedance 视频提交 VEED 视频口型同步；口型处理依赖两路结果，因此这一阶段不能提前并行。最终合成明确映射 IndexTTS2 音轨，不采用 Seedance 或口型服务附带的人声。两种配音路线都保留清晰字幕，不擦除、打码或模糊字幕区域。

已有历史任务继续按提交时的流程处理，未记录配音选择的旗舰模型任务沿用 Seedance 路线。新配音记录标记 `provider=fal`，保存每段的请求编号、状态和结果查询地址；已准备的历史配音记录未带该标记时仍使用 302.AI，不把旧任务编号发送到 fal，也不重新生成已付费片段。IndexTTS2 任务不在配音或口型处理失败时偷偷回退到原声；查询或配音下载暂时失败则继续查询和下载原任务。历史 302.AI 任务明确返回参考音频下载超时或 SSL 连接中断时，最多重试五次并保留已失败的任务编号；历史 fal 配音保留原恢复规则。新任务保存 `recoveryPolicy=1`，配音记录保存 `recoveryVersion=1`，按以下规则恢复：

- 情绪参考只能来自原视频。每段转为 24 kHz 单声道 PCM WAV 后，用 ffprobe 检查实际音频时长不少于 5 秒，并通过 VAD 确认存在人声；不能靠补静音、循环或改用音色参考来通过检查。原音轨不足 5 秒或反复检查无有效人声时，保存进度并等待素材调整。这里的 5 秒是情绪参考输入下限，成片的说话时间仍按原时间线对齐。
- 参考上传、状态查询、结果下载的暂时故障自动退避重试。已确认的配音失败会重新提取参考音频，仅重做该段，最多 3 次付费尝试（含首次）；已成功的段和已生成的视频保留。账户限制或内容审核问题不盲目重试。每轮处理（包括持续排队）超过 30 分钟，或素材整理连续 3 次未完成时，转为等待处理；继续处理会开启新的查询时窗，但不清零付费尝试次数。
- 提交回包丢失时，使用提交时间及完整输入匹配 fal 请求列表；只有唯一匹配且费用记录关联成功，才接回原请求。列表不完整、匹配不唯一或查不到记录时只继续核对，不重发生成。配音次数、等待时间、请求编号和历史失败请求均持久化。
- 页面使用“正在重新处理 / 进度已保存 / 等待继续处理”等状态，不展示上游技术错误；后台保留结构化诊断。不把未完成任务标为成功，也不无期限显示仍在生成。允许继续的任务从原阶段恢复，达到付费上限后不能通过继续按钮清零次数。停止处理只停止本任务的后续调度，已经发出的上游请求仍可能计费。
- 等待中的任务保留原费用预留，成功、主动停止或过期时核对结算；重试的失败请求也保留费用回执。未知费用保持待核对，不假定失败调用免费。仅在还未预留费用和提交视频时允许直接替换原素材；其他素材问题可停止后新建，旧记录仍保留。

新配音与口型、文件上传共用 `FAL_KEY` / `FAL_API_KEY` / `VIDEO_FAL_KEY`（按此顺序取第一个非空值），认证为 `Authorization: Key ...`。本地可在根目录 `.env.local` 配置，生产仅读取部署环境。`INDEXTTS_302_API_KEY` / `INDEXTTS_API_KEY` 与 `INDEXTTS_BASE_URL` / `INDEXTTS_API_BASE_URL` 仅用于历史 302.AI 配音恢复，不再决定新复刻配音或语音识别的上游；独立数字人模块不受此变更影响。口型模型复用 `FAL_VEED_MODEL`，默认 `veed/lipsync`。只有选择 IndexTTS2 的新任务在预留积分前检查两项服务配置；缺少这些配置不影响 Seedance 配音。Seedance 读取原素材使用 HMAC 签名；IndexTTS2 的参考声音和分段情绪音频，以及口型服务的生成视频和完整配音，由服务器上传至 fal 文件存储，持久化复用文件地址，设置 3 天过期，避免供应商直接访问网站时出现 SSL 下载失败。用户读取结果仍要求账号归属。到期清理包括分段音频和口型中间文件。

## 连接与部署

实现参照 `zxc9802/seedance` 的 `origin/main`，参考提交 `79f771740241904b7df7f1d40080d056d30d1c01`：

- 素材登记：`POST /openApi/material/create`，`type=1`，照片 `fileType=1`，视频 `fileType=3`，`thirdChannel=1`。
- 素材审核：`POST /openApi/material/pageList`，通过后使用 `asset://<materialId>`。
- 生成：`POST /openApi/generate`，标准版 `doubao-seedance-2-0-260128` / 至臻版 `doubao-seedance-2-5-260628` 共用 `fusion_video` 模式；照片写入 `resources`，视频写入 `referVideoUrl`。人物复刻属于视频编辑，两版均传 `scale=adaptive`、`duration=-1`，比例和时长跟随原视频，避免固定比例和时长被上游拒绝。任务仍保留原有比例与时长档位用于页面展示、预估和结算，不把 `-1` 写入任务时长。
- 声音参考以 `fileType=2` 登记，审核通过后写入 `referAudioUrl`。
- 查询：`POST /openApi/queryResult`，携带 `taskId` 和 `abilityType=VIDEO`。
- 以上接口认证均使用 `projectCode`、`X-Access-Key`、`X-Secret-Key` 请求头。

配置 `.env.example` 中的 `VIDEO_*` 与 `TEMP_ASSET_SIGNING_SECRET`。如素材服务使用相同项目，`MATERIAL_*` 可留空。开发环境读取 `.env.local`；生产仅从部署环境读取，密钥不进入浏览器或 Git。

`VIDEO_PUBLIC_BASE_URL` 必须是本项目服务可被供应商访问的 HTTPS 域名，生产默认使用启动器传入的 `AUTH_PUBLIC_URL`。例如本项目域名为 `https://nrcz.qycm.top`。不要填参考项目的 `PUBLIC_BASE_URL`，否则供应商无法下载本项目的上传文件。

供应商按请求的服务器出口 IP 校验白名单。与 Seedance 使用同一出口 IP、同一组项目凭据时，可沿用现有授权，不需要再放行开发电脑的 IP。开发电脑被拒绝不能说明部署服务器不可用；应从实际部署服务器验证素材服务权限。未授权时页面会明确提示，终止素材审核并退回积分，不会调用视频生成。

沿用现有 `/app/.data` 持久卷，数据位于 `.data/video/`。Docker 已包含 ffprobe；本地需安装 ffmpeg。采用现有单实例文件锁，不支持多个容器共享目录同时写入。反向代理需允许至少 300 MB 的请求体和视频的 Range 请求。

### 结果下载

模型完成后，由服务端下载和检查成片，页面显示已保存字节数；供应商提供总长度时，同时显示总长度。单次下载总超时为 10 分钟，连接超时 15 秒，无数据进展超时 30 秒，累计文件上限 200 MB。任务之间独立处理，一条下载缓慢的任务不会占住其他任务的查询队列。

下载中断会保留临时文件。只有相同结果 URL、强 ETag 及匹配的长度信息才能发送 `Range` / `If-Range` 接续下载，并严格校验 `206` 的起点、总长和 ETag。服务器返回 `200` 或不具备可靠实体标识时从头下载，避免拼接不同版本。已知总长度时，每 10 秒检查当前吞吐量；预计无法在本次剩余总时限内完成就提前中断。有未尝试的公开节点时，持续低于 128 KiB/s 且预计还需超过 30 秒，也会提前中断，保留慢节点记录并在重试时优先换节点。所有节点都尝试过后保留原总超时，避免整体带宽低时不断重下。未知长度和最后 64 KiB 沿用原超时规则。结果地址及每一次重定向均校验公开网络地址，DNS 连接固定到验证过的 IP。下载重试查询或保存同一模型任务，不额外调用生成接口。

供应商返回无查询参数的 `aggregationpic.buerdt.net` 链接时，优先通过其 DNS CNAME 指向的原生 TOS 桶域名下载相同路径。只接受 `*.tos-*.volces.com`，连接仍校验公开地址并固定 DNS；CNAME 查询、原生地址连接或 HTTP 状态不可用时回退原链接。带签名或其他查询参数的链接保持原样。断点元数据仍记录供应商原链接，跨域续传继续严格核对 ETag 与长度。

## 积分、恢复与保存

- 使用项目现有账号积分账本，按视频时长预留积分；成片通过 ffprobe 校验并保存后按实际时长结算，不超过本次预留金额。
- 素材审核失败、模型明确失败或任务超时退回预留积分；结算/退款服务故障会重试，结算完成前不开放结果下载。
- 持久化任务 ID，在同一任务上重复提交不会重复调用视频生成。已取得模型任务 ID 后，服务重启继续查询原任务。
- 失败后重新检查先完成原任务的退款，再使用独立账本 ID `video-recheck:<taskId>:<attempt>` 预留积分；保留原任务的退款记录，不修改已退款账目。复核通过只结算本次预留一次，复核失败退回本次预留。重复点击正在复核或已完成的任务不会新建预留；预留结果回包丢失或进程中断时，按持久化账本 ID 查账和退款，不再次付费生视频。
- 付费提交回包丢失或重启时尚未保存模型 ID：标记未确认并退回本项目预留积分，不自动再次付费提交。上游可能已执行，需核对供应商记录后再创建任务。
- 上传的原文件通过 24 小时 HMAC 签名链接供 Seedance 读取；IndexTTS2 和口型服务读取设置 3 天过期的 fal 文件地址。任务、结果与下载要求登录且归属当前账号。未提交素材 1 天后清理；已提交素材随任务保留 3 天，成功成片从完成时计 3 天。到期清理覆盖原素材、生成原片、成片、断点下载元数据、临时音频、VAD/ASR 中间文件和语音检查诊断，不只删除最终成片。任务编号和计费记录保留用于去重。

## 深度复刻全屏字幕与水印清理

深度复刻完成画面生成、分段拼接和声音合成后，自动调用无痕AI `video_removal_std`，固定使用 `method: all_area`，不传 `rect`，不依赖 OCR 或手工框选。原版复刻的字幕流程不变。清理后的画面重新合入清理前已确认的音轨，避免覆盖换声和背景声结果；没有原音轨时不会添加声音。

后端环境变量 `WUHENAI_API_KEY` 必须配置。临时存储优先复用完整的 `MIX_MATERIAL_COS_*` 四项，否则使用完整的 `COS_*` 四项。密钥仅从服务端环境读取，不能提交到 Git；生产需要在 Zeabur 配置环境变量，本地可放入忽略的 `.env.local`。缺少配置时，在提交付费视频生成前明确报错。

临时对象位于私有的 `workspace-video/subtitle-removal/<任务编号>/`，输入 GET 和结果 PUT 均使用 36 小时签名。清理结果下载、校验尺寸与时长、合回音轨后才开放预览下载。成功后删除临时云端对象，删除失败在任务到期清理时重试；清理中间文件随成片到期删除。

任务保存清理供应商编号、阶段、进度、时间与上游返回的用量。服务重启、查询失败、下载失败继续原任务，不重复提交。付费提交结果不确定或上游任务明确失败时暂停并保留原成片，禁止自动再次扣费；不会用马赛克、模糊、旧版局部修补或未经清理的成片冒充成功。现有用户生成积分定价不变，无痕AI从配置的供应商账户另行扣费。
