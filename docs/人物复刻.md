# AI 视频 · 人物 1:1 复刻

输入一段单个人物的视频，再输入一张目标人物照片，用 Seedance 2.0 替换视频中的人物。固定提示词要求遵循照片中的人物形象，保留动作、镜头和说话内容，自然表达情绪、表情，并且不出现字幕或文字。提示词中的 100% 是生成目标，不是相似度保证。

## 使用

1. 打开「AI 视频」，选择参考视频和目标人物照片。
2. 点击「上传素材，查看费用」。服务端检查视频时长与照片格式，显示生成时长和积分预估。
3. 点击「开始人物复刻」。素材审核、生成、保存与结算状态会自动更新；可离开页面，再从最近记录查看。
4. 成片可播放和下载，也会出现在「资产 → 视频」。成片保留 3 天。

### 声音参考

可额外上传一段清晰的单人 MP3 / WAV，2–15 秒、最大 15 MB，指定目标音色。参考音频的台词不进入成片；沿用原视频的台词、开口时间和停顿。未上传声音参考时沿用原有流程。

上传后先由 Silero VAD 检测原视频的人声区间，再由 Whisper 识别台词和字词时间戳。页面显示人声起点及逐段台词，可试听开口处；点击「确认台词，开始人物复刻」才预留积分并调用 Seedance。参考视频或声音改变后必须重新分析。无音轨、无可识别人声、时间戳异常或识别与检测冲突会阻止提交。

Seedance 收到照片、视频、独立音频素材及原视频的语音时间线。成片保存前再次识别；只有原台词逐字匹配才校正声音。按原人声区间修正各段语速、开始时间和停顿，再重新识别校正后的成片；每段起止偏差均不超过 100 毫秒才完成并结算。失败不重新调用视频生成，退回预留积分。检测精度受素材质量影响，100 毫秒是验收阈值，不是识别准确率保证。

此版本对齐的是声音时间线，仍需预览核对参考音色和画面口型；音轨校正不会重新制作口型。音频校正以口播区间为准，不保证保留背景音乐及口播区间外的声音。强背景音乐、多人对话、重叠说话应先整理素材。

语音识别使用 `VIDEO_TRANSCRIPTION_API_KEY` / `VIDEO_TRANSCRIPTION_BASE_URL`，也可沿用 `MOTION_API_KEY` 或 `INDEXTTS_302_API_KEY`。Docker 已安装 ONNX Runtime，默认复用 `MIX_PYTHON_BIN`；本地设置 `VIDEO_PYTHON_BIN` 指向安装了 numpy、onnxruntime 的 Python。Silero 模型固定来源提交 `1e261b036686cd0017d500ee96acd1c4ba572a9d`，文件 SHA-256 为 `1a153a22f4509e292a94e67d6f9b85e8deb25b4988682b7e174c65279d8788e3`，许可证见 `services/video/SILERO_LICENSE`。

参考视频支持 MP4/MOV，2–15 秒、最大 50 MB、宽高至少 300 像素。照片支持 JPG/PNG/WebP，最大 10 MB、宽高至少 300 像素，服务端转换为去除元数据的 JPEG。输出为 720p，开启音频。生成时长取不短于参考视频的最近支持值（4、5、6、8、10、12、15 秒），比例取最接近参考视频的支持比例。

## 连接与部署

实现参照 `zxc9802/seedance` 的 `origin/main`，参考提交 `79f771740241904b7df7f1d40080d056d30d1c01`：

- 素材登记：`POST /openApi/material/create`，`type=1`，照片 `fileType=1`，视频 `fileType=3`，`thirdChannel=1`。
- 素材审核：`POST /openApi/material/pageList`，通过后使用 `asset://<materialId>`。
- 生成：`POST /openApi/generate`，模型 `doubao-seedance-2-0-260128`，`fusion_video` 模式；照片写入 `resources`，视频写入 `referVideoUrl`。
- 声音参考以 `fileType=2` 登记，审核通过后写入 `referAudioUrl`。
- 查询：`POST /openApi/queryResult`，携带 `taskId` 和 `abilityType=VIDEO`。
- 以上接口认证均使用 `projectCode`、`X-Access-Key`、`X-Secret-Key` 请求头。

配置 `.env.example` 中的 `VIDEO_*` 与 `TEMP_ASSET_SIGNING_SECRET`。如素材服务使用相同项目，`MATERIAL_*` 可留空。开发环境读取 `.env.local`；生产仅从部署环境读取，密钥不进入浏览器或 Git。

`VIDEO_PUBLIC_BASE_URL` 必须是本项目服务可被供应商访问的 HTTPS 域名，生产默认使用启动器传入的 `AUTH_PUBLIC_URL`。例如本项目域名为 `https://nrcz.qycm.top`。不要填参考项目的 `PUBLIC_BASE_URL`，否则供应商无法下载本项目的上传文件。

供应商按请求的服务器出口 IP 校验白名单。与 Seedance 使用同一出口 IP、同一组项目凭据时，可沿用现有授权，不需要再放行开发电脑的 IP。开发电脑被拒绝不能说明部署服务器不可用；应从实际部署服务器验证素材服务权限。未授权时页面会明确提示，终止素材审核并退回积分，不会调用视频生成。

沿用现有 `/app/.data` 持久卷，数据位于 `.data/video/`。Docker 已包含 ffprobe；本地需安装 ffmpeg。采用现有单实例文件锁，不支持多个容器共享目录同时写入。反向代理需允许至少 50 MB 的请求体和视频的 Range 请求。

## 积分、恢复与保存

- 使用项目现有账号积分账本，按视频时长预留积分；成片通过 ffprobe 校验并保存后按实际时长结算，不超过本次预留金额。
- 素材审核失败、模型明确失败或任务超时退回预留积分；结算/退款服务故障会重试，结算完成前不开放结果下载。
- 持久化任务 ID，在同一任务上重复提交不会重复调用视频生成。已取得模型任务 ID 后，服务重启继续查询原任务。
- 付费提交回包丢失或重启时尚未保存模型 ID：标记未确认并退回本项目预留积分，不自动再次付费提交。上游可能已执行，需核对供应商记录后再创建任务。
- 上传的原文件只通过 24 小时 HMAC 签名链接供供应商读取；任务、结果与下载要求登录且归属当前账号。未提交素材 1 天后清理；已提交素材随任务保留 3 天，成功成片从完成时计 3 天。任务编号和计费记录保留用于去重。

## 验证

`npm run test:video` 检查连接协议、签名、账号隔离、校验、积分预留/退款/结算、重复提交、重启恢复及到期清理。`npm run check`、`npm test` 和 `npm run build` 用于项目回归及构建。macOS 若临时目录是符号链接，可用 `TMPDIR=/private/tmp npm test`；账本按现有规则拒绝符号链接目录。

真实模型验收还需可访问的 HTTPS 素材域名、供应商 IP 授权和可用额度。模拟接口测试只能验证页面与任务流程，不能代替真实成片的相似度、情绪和口型评估。

2026-10-08 已配置并部署到 `https://nrcz.qycm.top/#video`，使用与 Seedance 相同的服务器出口及供应商项目凭据，服务器素材查询成功，无需额外授权开发电脑 IP。Computer use 使用独立验收账号，经仅绑定本机回环地址的代理隔离登录 Cookie，所有页面、上传、任务和结果请求均转发到生产服务，没有模拟生成响应。

真实验收使用虚构女性的 5.088 秒口播视频和另一位虚构男性的照片，实际生成 720×1280、约 6.06 秒含音频的视频。抽查不同时刻的画面，确认人物已替换为目标男性，灰发、眼镜、蓝色上衣、微笑和挥手可见；原场景保留，抽查未见字幕。原视频与结果的语音转写一致。页面播放、下载、刷新恢复及资产库收录通过；生产账本仅有一次 67 积分预留和一次结算，余额从 1000 变为 933、冻结归零。此记录验证本次样例，不保证所有输入达到完全一致的外貌或表演效果。
