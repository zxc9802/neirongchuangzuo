# 调用控制与清理验收

日期：2026-09-30。本轮只处理 Agent / AI 图片的稳定性、重复调用与全站额度、生成结果清理。不包含账户隔离、视频、混剪和数字人生成链路；未执行服务器部署。

## 调用与额度

- 默认全站每日图片 20 次、对话 100 次，每分钟两类共 10 次；北京时间零点重置。`.env.example` 提供修改项，值必须为非负整数，0 表示禁用。
- 请求发出前持久化预占和发送标记。未发出的失败释放名额；已发送的失败、断流或超时保守计次，不自动返还或重试。额度控制是尝试次数，不是实际金额，供应商可能有不同计费规则。
- 图片和对话都必须携带 UUID `requestId`。同标识同内容返回原结果，换内容拒绝；统一 UUID 大小写，防止 Windows 路径别名绕过去重。对话取消接收、超时或刷新后用原 ID 查询，按钮显示“查询原回答”。明确修改需求重新发送才会建立新调用。
- 账本位于 `.data/ai/.runtime-control/requests.json`，只存标识、摘要、状态、模型、时间和供应商返回的可用用量。状态接口隐藏摘要和请求正文。它不是供应商余额接口。
- 同一数据目录只能运行一个实例。第二实例拒绝启动；只在确认同机原 PID 已退出时接管锁。多进程、多台服务器或多容器不能绕过锁共享这个目录，后续应采用共享数据库和队列。
- 服务重启把未发送记录取消、已发送未确认记录标为不确定；不会恢复付费执行。旧任务与历史生成不会被补扣新额度。
- 不要删除账本或任务记录来“清空额度”；这会破坏重复调用保护。异常锁需确认原进程已退出后排查，不以锁的年龄强制接管。

## 稳定性和清理

- 非法地址、损坏 HTTP、异步异常统一返回可读错误，不退出进程、不回显供应商错误正文。AI 请求体限制 34MiB，总上传时间限制 30 秒；数字人流式大文件代理保持原有能力。
- 图片下载校验协议和公网地址、固定每跳 DNS，重定向地址受错误边界保护；下载过程有 60 秒总截止。模型请求中断不会自动重新提交。
- 持久化失败暂停新调用，避免在无法记录时继续付费。正常关闭先拒绝新提交，等待上传处理和已有调用完成，停止清理后释放独占锁。
- 服务初始化完成才监听，初始化即清理，之后默认每分钟清理。成功图片和可查询的对话答案完成满 72 小时后禁止读取；失败和中断任务的半成品立即删除。
- 缺失或损坏任务记录的孤儿结果按文件修改时间清理。只删除 UUID 目录内固定生成结果名，不递归删除、不跟随 junction/symlink，不清理上传原图或未知文件。
- 清理失败立即隐藏到期结果，输出不含私密路径的告警，下次继续尝试。`GET /api/ai/usage` 返回每日额度、近期状态、`healthy` 与清理时间、待处理数量和失败统计。`GET /api/ai/status` 在原配置状态之外返回相同运行信息，图片页面显示今日剩余。
