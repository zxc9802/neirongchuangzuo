# 注册邀请码管理

邀请码为6位数字与大写字母的组合，至少包含一个数字和一个字母。每个码只允许成功注册一次；大小写和首尾空格会自动规范化。数据库只保存摘要，不保存明文，账号删除也不会使已使用的邀请码恢复可用。

管理工具只使用独立账号库 `AUTH_DATABASE_URL`，不会连接旧账号库。请通过容器环境或 `services/digital-human/.env.local` 配置连接；工具拒绝与 `INTERNAL_AUTH_DATABASE_URL` 相同的数据库地址。数据库账号需要创建 schema、建表及读写 `digital_human_auth.registration_invites` 的权限。连接密码不要提交到 Git。

## 本地生成与保存

在项目根目录执行。先自行创建一个仅管理员可访问、位于代码仓库外的目录，将下面路径替换为实际的绝对路径：

```powershell
node services/digital-human/scripts/registration-invites.mjs generate --count 20 --days 7 --out "C:\Users\Administrator\PrivateInvites\registration-invites-20261007.txt"
```

默认数量为20，单次最多1000；省略 `--days` 时不设置过期时间，指定时为1—3650天。文件必须不存在，工具不会覆盖已有文件，也不会自动创建目录。只允许仓库外私有目录，或经 Git 验证明确忽略且未跟踪的文件；经过符号链接的目录会被拒绝。

终端只显示生成数量，明文逐行保存在指定 UTF-8 文本文件。文件在 Linux 使用仅所有者可读写的权限；Windows 目录权限请由管理员设置。不要把邀请码文件放到网站公开目录、Git、共享日志或截图中。需要分发时直接从私有文件读取；数据库不能恢复明文，因此请保留安全备份。

## 部署容器中生成与取回

在运行独立账号库配置的数字人容器中使用 Node 24。将 `digital-human-container` 替换为实际容器名：

```sh
docker exec digital-human-container node /app/services/digital-human/scripts/registration-invites.mjs generate --count 20 --days 7 --out /tmp/registration-invites-20261007.txt
docker cp digital-human-container:/tmp/registration-invites-20261007.txt /home/ubuntu/private-invites/registration-invites-20261007.txt
chmod 600 /home/ubuntu/private-invites/registration-invites-20261007.txt
```

宿主机私有目录需提前创建并限制访问。`/tmp` 位于项目外，生产镜像不必安装 Git；项目内部没有 Git 可验证时禁止导出。使用你们已有的安全文件传输方式取回文件，确认备份后可移除容器中的临时副本。以上是管理员操作示例，运行时仅操作配置的独立账号数据库。

当前线上使用 K3S，管理员也可在服务器按实际 namespace/pod 操作：

```sh
sudo kubectl -n <namespace> exec <pod> -- node /app/services/digital-human/scripts/registration-invites.mjs generate --count 20 --out /tmp/registration-invites.txt
sudo kubectl -n <namespace> cp <pod>:/tmp/registration-invites.txt /home/ubuntu/private-invites/registration-invites.txt
chmod 600 /home/ubuntu/private-invites/registration-invites.txt
```

## 查询和撤销

```powershell
node services/digital-human/scripts/registration-invites.mjs list
node services/digital-human/scripts/registration-invites.mjs revoke --code A1B2C3
```

`A1B2C3` 只是格式示例。`list` 只显示未使用、已使用、已过期的数量，不输出明文或摘要。撤销只影响未使用的邀请码；被撤销的摘要会保留并计入已过期，防止以后随机碰撞重新启用相同的码。已使用的邀请码不能通过撤销解除绑定。

参数、写盘或入库失败时工具退出失败，提交前会尝试回滚并删除此次新建的输出文件。若提示“数据库提交结果待核对”，说明提交确认丢失，服务器可能已经提交；此时会保留私有输出文件。不要直接分发或盲目重跑，应由数据库管理员核对该批文件中邀请码的摘要是否存在及其状态。汇总数量不足以证明某一批码是否已提交。

撤销命令中的真实邀请码可能进入管理员终端历史；请遵守你们的私有终端和历史记录管理要求。
