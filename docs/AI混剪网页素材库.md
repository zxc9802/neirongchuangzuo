# AI 混剪网页素材库

在现有 AI 混剪页面点击「选择素材文件夹」，递归读取电脑中的视频。选择目录只授权网页读取，不会上传整个素材库。上传按钮下显示「素材正在上传」和进度条，按整个目录中的视频数统计；等待压缩或转换的文件也计入总数，全部片段分析成功且原片可读的文件才计入完成数量。制作时传输原片则显示实际字节进度。

原视频保留在电脑中。浏览器把视频切成最长八秒的分析区间，读取低清 JPEG 帧；服务器临时合成分析视频，调用多模态 embedding 和描述模型，长期保存片段描述、向量及版本记录。输入完整宣传文案后，服务器进行向量召回、重排和画面核验，浏览器按需上传命中的原视频，服务器取片、配音、添加字幕并编码成片。

扫描视频时长和抽帧分析分别最多同时处理三项，完成一项立即补入下一项。每个片段的向量与画面描述同时请求；一项成功、一项失败时分别保存结果，重试只补失败的一项。先处理所有正常片段，再处理失败片段与源文件修复。网络中断、请求超时、限流和服务端临时错误按 15、30、60 秒的间隔持续重试，避免两次失败后永久停止；其他分析错误每次扫描最多自动重试一次。分析或修复报错后，即使后台仍在自动重试，也显示「重试未完成素材」；点击立即重新处理，复用已完成的分析结果。视频明确报错就移到修复队列，无响应的解码操作最多等待 5 秒。

超过 512 MiB 或浏览器无法解码的源文件在正常索引完成后由本机后台自动修复。兼容 H.264/AAC 的 MOV 优先无损换封装为 MP4；其余情况转为 H.264/AAC MP4，最高 1080p、目标不超过 480 MiB，并验证完整时长、音轨和实际输出大小。大型转码一次处理一个，避免占满内存；原文件不改动，成功副本按账号与源文件版本保存在 IndexedDB，后续索引和临时上传复用该副本。首次修复按需从本站加载约 31 MiB 的 FFmpeg 运行时；2 GiB 及以上输入暂不支持浏览器自动修复，会保留明确错误。压缩时长取决于原片、浏览器和电脑性能。

## 用户流程

1. 首次选择素材文件夹，等待至少一个片段向量化完成。
2. 输入宣传文案，选择比例、720p 或 1080p、是否添加字幕；选择合成人声或保留素材原声，可选背景音乐，开始混剪。
3. 制作时保持网页打开、电脑联网。成片可在原预览区播放和下载。
4. 再次打开网站时，目录授权有效就自动后台增量扫描。新增或修改的文件重新分析；未修改的文件复用服务器向量。权限失效时点击重新连接。

每次制作一条视频。合成人声时，时长由完整文案配音确定；保留素材原声时不调用配音模型，按文案阅读速度估算画面和字幕时间，保留所选片段的原声音。素材列表只显示部分预览，目录索引与检索使用所有已分析素材。

### 音色与背景音乐

剪辑设置中可上传、试听、选择和删除自己的音色与背景音乐，支持 MP3、WAV 和 M4A。音色上传最大 32 MiB，取前 15 秒转换为配音参考；背景音乐最大 128 MiB，保留上传文件。合成人声使用选中的音色，或管理员配置的默认音色。保留素材原声只关闭合成配音，素材本身的声音仍会保留；没有音轨的素材对应区间保持安静。

两种方式都能选背景音乐。短音乐循环、长音乐裁至成片时长，加入淡入淡出，并在有人声时降低配乐音量。音色和音乐保存在同一个私有 COS 桶的 `mix-audio/` 目录，按已登录账号隔离；列表只返回本站试听地址，试听时签发短期链接。音频库不会随成片到期删除，用户主动删除；可恢复的制作任务仍引用的音频暂不能删除。SQLite 音频元数据同样保存在 `/app/.data` 持久卷中。

桌面 Chrome/Edge 优先使用 File System Access API，并在 IndexedDB 保存授权句柄。兼容目录输入的浏览器可选择文件夹，但刷新后需要再次选择；服务器向量可以复用。HTTPS 是线上使用要求。网页关闭或电脑离线后不能扫描本机，服务器等待所需素材并保留已完成阶段。

## 账号与存储

主站复用现有账号服务验证会话，派生稳定账号标识注入内部混剪服务。浏览器传来的账号标识不参与授权。目录、任务列表、任务状态及成片都校验账号归属；浏览器目录句柄和任务标识同样按账号保存。

服务器数据位于持久化 `.data/mix/`。SQLite 保存片段描述和归一化向量，查询时只加载当前目录的向量矩阵。原片不写入数据库。临时源文件最大 512 MiB/条，每目录临时素材配额 2 GiB、服务器总配额 10 GiB，整原片缓存最长 24 小时；已提取的片段与任务输入在任务结束后 24 小时清理，等待中的请求最长保留 7 天以支持续作。成片保留 72 小时，任务记录保留 30 天。索引代理在模型分析后删除。首次分析仍有模型费用，命中素材传输仍有带宽及短期存储成本。

按原文件相对路径、大小和修改时间检测版本，自动修复不改变版本标识。仅改名视为新版本；内容变更但大小和修改时间均未变化时无法检测。扫描失败不会撤销尚未访问到的素材。自动修复仍失败的视频显示文件名和原因，可在处理源文件后重新扫描。

## 部署

生产 Docker 已加入 Python 虚拟环境、FFmpeg 和 CJK 字体。Node 主站在首次素材/混剪请求时启动仅监听回环地址的 Python 服务，生成内部访问密钥并管理其生命周期。Python 端口和密钥不会交给浏览器，也无需公开额外端口。

在部署环境配置以下服务端变量（本地开发可在主站 `.env.local` 配置）：

| 变量 | 用途 |
| --- | --- |
| `OPENLUX_API_KEY` | 已有 OpenLux 密钥，素材 embedding、描述和画面核验 |
| `RERANK_API_KEY` | 文本重排服务密钥 |
| `RERANK_URL` | 使用 OpenLux 重排时设置为 `https://api.openlux.ai/v1/rerank` |
| `INDEXTTS_302_API_KEY` | 已有 IndexTTS2 配音密钥；仅合成人声需要 |
| `INDEXTTS_SPEAKER_AUDIO_URL` | 可选的管理员默认音色 HTTPS URL；选择上传音色时不需要 |
| `INDEXTTS_EMOTION_AUDIO_URL` | 可选的情绪参考 HTTPS URL |
| `INDEXTTS_EMOTION_AUDIO_PATH` | 可选的情绪参考文件路径，可替代上面的 URL |
| `MIX_AUDIO_COS_SECRET_ID` | 填音频桶的 SecretId，仅服务端保存 |
| `MIX_AUDIO_COS_SECRET_KEY` | 填音频桶的 SecretKey，仅服务端保存 |
| `MIX_AUDIO_COS_BUCKET` | `hjyp-1410143389` |
| `MIX_AUDIO_COS_REGION` | `ap-singapore`（新加坡） |

音频库的四项 COS 配置须全部填写，账号需要对象上传、读取、删除权限。不要用这些变量替换其他功能的 `COS_*` 配置，也不要公开桶访问权限。没有配置音频桶仍可制作不带配乐的原声视频；音色与音乐库不可用。配置后重新部署，使 Node 主站及其 Python 子进程都获得新变量；Docker 会安装音频库 SDK，已有手动部署需重新安装 `services/mix/python/requirements.txt`。

没有配置情绪参考时使用通用情绪向量，不需要用户上传情绪参考。可选覆盖 `EMBEDDING_URL`、`LLM_URL`、`RERANK_URL`、`INDEXTTS_BASE_URL`、`INDEXTTS_DOWNLOAD_HOSTS`。这些是固定部署配置，不能来自用户请求。成片仍通过本站受保护下载接口交付。继续挂载 `/app/.data` 和数字人的运行目录；不要部署多个进程共用同一混剪数据目录。

同一 OpenLux 密钥可分别配置到 `OPENLUX_API_KEY` 和 `RERANK_API_KEY`，对应 `gemini-embedding-2-preview`、`gemini-3.7-flash` 和 `qwen3-rerank`。此时必须同时设置上表的 `RERANK_URL`；未覆盖时重排仍使用 302 地址，不能混用服务商密钥。IndexTTS2 使用单独的 302 配音密钥。

取片统一到最终 25 FPS，并按方向限制到最高支持的 1920×1080 或 1080×1920，不放大小尺寸原片。HDR 按线性光色调映射为 BT.709 SDR，普通 BT.709 原片保留色彩；提取片段使用 H.264 CRF 0，避免增加一次有损压缩。最终交付为 H.264 CRF 16、8 位 BT.709 SDR，中间文件会占用更多临时空间。它保留的是帧率、尺寸与色彩转换后的像素，不保留原始 4K/60 FPS/HDR 规格。

本地首次使用：

```powershell
python -m venv .mix-venv
.mix-venv/Scripts/python.exe -m pip install -r services/mix/python/requirements.txt
# 主站 .env.local 设置 MIX_PYTHON_BIN 为这个 Python 的绝对路径
npm run dev
```
