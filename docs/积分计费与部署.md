# 起芽内容创作积分

## 当前规则

同一账号的通用图片、餐饮图文、AI混剪和数字人共用一个钱包。新账号及尚未建立钱包的已有账号，在第一次读取或使用积分时获得1000积分，数据库唯一记录保证仅赠送一次。

| 内容 | 结算方式 |
| --- | --- |
| 通用图片 | 每张实际交付图片50积分；套图中失败的图片不扣分 |
| 餐饮图文 | 每张实际交付图片50积分；封面替换第一张图片，不额外计数，ZIP不计数 |
| 混剪、数字人 | `ceil(实际成片秒数 × 333 / 30)` |

30秒333积分，60秒666积分，3条实际30秒共999积分，剩1积分。时长包含小数，不按30秒一档计费；例如1秒12积分，30.1秒335积分。时长由服务端读取音视频文件确认，前端显示的估算不作为扣分依据。

上传、照片分析和推荐方向不扣用户积分；对话沿用现有调用限制。独立AI视频尚未接入真实生成，不扣积分，也不显示虚假生成结果。原系统外部SSO数字人的既有计费保留原规则，不混入本站钱包。

## 预留与结算

提交正式生成前冻结预计所需积分，不足时在调用生成服务前返回402 `INSUFFICIENT_POINTS`。成功后按实际交付数量或时长结算，释放差额；实际时长增加时，服务端原子追加预留，无法覆盖时不交付未结算成品。

自动重试沿用原任务，不重复扣分。手动重新生成使用新的计费任务标识。数据库使用账号级事务锁和唯一账本事件，刷新、并发提交、回调及丢失响应不会重复赠送或扣分。

明确生成失败释放预留。付费服务提交结果不确定时，保留预留并查询原任务，不自动再提交付费任务。成品已保存但扣分响应不确定时，保留原成品并恢复原结算，不重新生成；结算完成前禁止下载。混剪预留响应不确定时显示“积分确认中”，通过原任务重试确认。

图片及下载包仍保留3天，餐饮文字任务保留30天。过期的未交付图片释放未结算预留；已成功结算的记录不因图片到期而退款。餐饮任务清理保留最小财务关联，数据库恢复后继续释放，不因30天删除任务丢失冻结积分。

## 部署

生产环境必须配置 `AUTH_DATABASE_URL`。主站Node服务和数字人Next服务读取同一地址，自动创建 `workspace_credits` schema中的钱包、预留和账本表，不需要手工导入初始积分。生产缺少数据库配置直接报错，不能使用本地JSON钱包代替。

本地开发及测试可注入文件钱包，文件写入带进程锁和原子替换，目录应在忽略的`.data`内。不要把本地测试钱包、账号数据或环境变量文件提交Git。

主站 `GET /api/workspace/credits` 根据已验证登录会话返回可用积分、冻结积分和单价，不接受前端指定账号。浏览器不保存积分账本，生成或查询任务后重新读取余额。混剪Python通过仅绑定回环地址且需要私有令牌的内部桥接访问同一钱包，业务接口不能指定钱包所有者。

现有全站每日供应商调用上限继续生效，它与用户积分分别控制接口成本和用户余额。积分不是第三方模型的token计价，也不是人民币报价。本次未增加充值、购买积分或管理员调账入口。

## 验证入口

- `npm run check`：包含积分服务、前端及混剪桥接语法检查。
- `npm test`：包含真实文件钱包、真实PostgreSQL兼容事务、HTTP图片/餐饮扣分、跨模块并发、前端余额隔离与故障恢复测试。
- `npm run test:digital-human`、`npm run check:digital-human`、`npm run build:digital-human`：数字人计费、实际时长、恢复及构建检查。
- Python混剪测试包含预留响应丢失、恢复、失败释放、实际时长结算和并发归属检查。

线上验证应检查新部署版本、数据库连接、未登录访问401及静态模块发布。余额测试使用测试账号；不要通过清空账本或重新建立账号来验证初始赠送。
