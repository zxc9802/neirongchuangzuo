# 1:1 复刻与数字人故障排查

检查日期：2026-10-20。范围包括浏览器上传、任务提交、上游队列查询、素材传输、配音拼接、口型生成及结果恢复。

## 已确认并修复的问题

| 问题 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| 配音时间范围无效 | 上游成片略短于参考视频，原配音片段结束时间超过成片时长，拼接阶段失败 | 按实际成片时长等比例压缩配音时间轴，保留各段台词与相对停顿；必要时声音会略微加速 |
| 上传或提交长期无响应 | 浏览器网络请求一直不结束，页面停留在忙碌状态 | 为上传、提交及上传授权设置超时，允许用户查询原任务状态 |
| 数字人分片上传被短暂网络波动中断 | 分片 PUT 或完成确认遇到断网、408、429、5xx | 重试原分片及完成确认；401、403 等明确拒绝立即停止 |
| IndexTTS 已提交任务被误判失败 | 查询原任务或读取结果时短暂断网、限流、网关异常 | 在既有截止时间内重试读取原任务，不重复创建付费任务 |
| 数字人口型任务存在重复提交风险 | 付费 POST 已到达上游，但响应丢失，适配器自动重发 | fal 和 OpenLux 的付费创建请求只发送一次，保留提交结果不确定的状态 |
| fal 素材上传被本地地址策略误拦截 | fal 返回 S3 或 Cloudflare Storage 的签名上传地址 | 为签名 PUT 单独允许对应存储域名；控制接口仍使用原域名限制，上传 PUT 不携带 API Key |
| VEED v2 恢复查询地址错误 | 使用带模型子路径的地址拼接队列查询 URL | 按 owner/application 构造恢复地址，正常提交仍优先使用上游返回的查询地址 |
| fal 明确生成失败后仍长时间轮询 | 队列显示完成但携带 error，或结果接口返回明确的失败 | 识别终止错误，立即结束并显示原因 |
| 口型已生成但下载失败导致任务失败 | 结果下载遇到短暂网络问题 | 保存原结果地址并重试下载，重启后也继续使用原任务 |
| fal 素材存储鉴权失败被显示为持续重试 | 存储初始化返回 401、402、403 等明确拒绝 | 显示密钥、权限、余额相关提示及 HTTP 状态；网络波动仍可重试 |
| 只配置 fal 时，重启后未主动恢复复刻任务 | 服务启动检查只覆盖另一条模型线路 | fal 已启用时也初始化复刻服务并恢复已有任务 |
| 两个模块的 fal 密钥配置不一致 | 只配置 VIDEO_FAL_KEY，复刻可用但数字人口型识别不到 | 数字人统一兼容 FAL_KEY、FAL_API_KEY、VIDEO_FAL_KEY |
| 上游 IP 白名单错误被通用提示覆盖 | Qiya 明确拒绝服务器 IP | 保留具体 IP 限制错误；网关错误按提交未确认处理，不自动重发付费请求 |

保留用户已明确要求的行为：不恢复“成片缺音或时长偏差就拒绝交付”的校验。配音拼接仍需有效的时间片段，本次通过适配时间轴解决已确认的越界情形。

## 最新截图的解释

10 月 20 日 12:48 的 PixVerse Swap 记录显示成片时长为 14.709 秒，错误是“配音时间范围无效”。旧代码在任一配音片段结束时间超过成片时长时就会产生这一错误，因此与本次修复的问题相符。

尚未读取该条线上任务的完整时间轴与后台日志，不能仅凭截图排除其他无效片段原因。声音参考的 10 秒时长用于提供音色，不等于最终整段配音的时长。已有失败记录不会因代码更新自动重新生成。

以下属于可能导致失败的运行条件，不代表本次已确认在线上发生：

- 登录过期、浏览器扩展或代理拦截上传、对象存储 CORS 配置不匹配。
