# 上线准备审查：Agent、AI 图片及主站接口边界

审查日期：2026-09-30。范围：`services/ai/server.mjs`、`preview.mjs`、相关 Agent / 图片前端调用与启动脚本。结论针对正式多人使用；当前服务仍只监听本机，不表示已经发生公网数据泄露。

本轮只读审查实现；未修改业务代码，未调用真实收费模型，未改动真实任务文件。在线验证仅查询、HEAD 和状态读取；异常验证使用临时存储、模拟供应商或单独临时子进程，均已结束并清理。根项目全量测试由主审统一执行。

## 结论

Agent 与图片生成已具备单人本机使用的真实链路和若干重要保护，但**不能直接作为面向多商家的正式服务开放**。主要阻断是账号与作品归属缺失、生产访问入口尚未建立、费用控制与跨进程任务一致性不足。成品 72 小时访问限制已实现，但异常半成品与冷启动清理存在补齐项。

## 具体发现

### AI-01 · P0（公开多人上线阻断）：AI 接口没有登录和用户归属

- 证据：`services/ai/server.mjs:275` 仅检查 Host / Origin / Fetch Metadata；`server.mjs:298` 读取整个进程的任务；`server.mjs:306` 按 ID 取任务；`server.mjs:284` 按任务 ID 读取成品；`server.mjs:338` 建立的任务没有用户或商家字段。`preview.mjs:51` 先处理 `/api/ai/*`，这些接口不会经过数字人服务的账号鉴权。
- 实际验证：不带 Cookie 的 `GET /api/ai/images?completed=true` 返回 200、5 个现有任务；换成任意 Cookie 仍返回相同 ID 集合；匿名任务详情返回 200 且包含完整 prompt；对应图片 HEAD 返回 200。报告没有记录用户文案正文。
- 影响：一旦通过代理放开访问，不同商家可以看见、下载同一份作品列表和创作要求，并共用同一模型凭据消费。UUID 和仅隐藏页面按钮不能提供用户隔离。接好数字人登录也不会自动保护这套独立接口。
- 上线前行动：在主站统一校验公司会话；给任务、媒体、幂等请求加入 `tenantId/userId`；所有列表、详情、下载和提交都执行归属与权限检查。完成匿名拒绝、A 用户无法查询/下载 B 用户结果的双账号验收。

### AI-02 · P1：现有入口是本机开发入口，正常生产域名无法使用

- 证据：`preview.mjs:73` 固定监听 `127.0.0.1:5173`；`services/ai/server.mjs:275` 只接受 localhost 主机名。`preview.mjs:24` 将转发协议固定为 `http`。根 `package.json:7` 仅有开发启动命令；`scripts/dev.mjs:55` 拉起的是 `next dev`。
- 实际验证：对现有服务发送 `Host: release-audit.invalid` 的无副作用状态查询，得到 403 / `HOST_REJECTED`。
- 影响：保留公网域名转发时图片与 Agent 会被拒绝；简单伪装为 localhost 来绕开检查，也没有补上账号权限。代理协议与登录回跳需要在 HTTPS 域名下统一核验。
- 上线前行动：建立独立生产启动方式及明确的可信代理 / 域名配置；由 HTTPS 入口统一路由主站、AI、数字人服务，数字人用生产构建启动。生产 Host/Origin 白名单应与账号鉴权一起设计，不能删除本机限制后直接发布。

### AI-03 · P1：畸形请求地址可终止主站进程

- 证据：`preview.mjs:50` 在 async HTTP 回调中直接 `new URL(req.url, ...)`，没有请求级 try/catch；该回调的 rejected promise 没有统一处理。
- 隔离复现：启动单独的临时 `createPreviewServer()` 子进程，发送 request-target `http://[`。子进程退出码为 1，错误为 `ERR_INVALID_URL`，栈指向 `preview.mjs`。未对用户当前运行的服务执行此请求。
- 影响：直接暴露该 Node HTTP 入口、或代理放行这种请求目标时，一个畸形请求就会中断所有用户任务；上线代理可能提前挡住，但应用本身仍应安全返回 400。
- 上线前行动：对 URL 解析、路由分发和异步 handler 加统一错误边界；非法请求返回 400，运行时异常返回脱敏 500 并记录关联 ID。增加“畸形请求后下一个正常请求仍成功”的验收。

### AI-04 · P1：只有全局并发限制，没有商家额度、消费记录或 Agent 幂等

- 证据：`services/ai/server.mjs:130` 使用进程内 `busy` 与 `chatCount`；`server.mjs:315` 最多 3 个对话；`server.mjs:336` 最多 1 个图片任务。`server.mjs:312` 在这些限制前已经读取请求体。`server.mjs:318` 调模型后只返回文字和模型名，不记录 provider request ID、usage 或业务扣费流水。`design/agent-chat.js:275` 只提交 messages，无服务端幂等标识。
- 影响：并发数限制不等于消费上限，用户可连续消耗公司模型余额；一个用户占满全局并发会让其他商家不可用。Agent 刷新/断连/手动重试没有任务可查询，可能重复计费。输入大小已有单次上限，但并发上传在业务并发检查前分配内存。
- 上线前行动：账号级、商家级和系统级请求限流；每次调用预占额度，明确成功结算、确定失败释放、结果不确定待核对的规则；持久化请求 ID、供应商请求 ID、耗时、用量和结算状态。请求体读取前就执行身份、额度与上传并发闸门。Agent 加幂等标识和断连后结果查询，或明确并落实可接受的计费策略。

### AI-05 · P1：重启不能续接生成，多个实例会重复付费

- 证据：`services/ai/server.mjs:130` 的任务索引、锁和并发均在单进程内；`server.mjs:215` 启动时把 queued/running 直接改为 failed / INTERRUPTED；`server.mjs:251` 的原图只在当次内存中；`server.mjs:331` 的幂等检查仅查询当前进程 Map。没有跨进程唯一约束、租约或上游结果对账。
- 隔离复现：两个 handler 共用同一个临时 storageDir，分别完成初始化后同时提交完全相同的 requestId 和内容；两边都返回 202，模拟供应商被调用 2 次。没有真实模型消费。
- 影响：更新部署或重启可能使“供应商已执行”的结果丢失；进程集群或滚动发布重叠期间可能同一请求付费两次。现有策略不会自动重试，这是正确的保守保护，但还不能提供正式业务恢复能力。
- 上线前行动：数据库中对“商家 + requestId”设唯一约束，持久化任务状态；使用持久化 worker 队列与分布式执行租约。补充运行中优雅退出、上游请求对账和结果恢复方案。在完成这些之前，试用环境只能明确限制为单实例，并安排生成任务清空后的停机更新。

### AI-06 · P1：失败/中断任务的已生成半成品不会按 3 天清理

- 证据：`services/ai/server.mjs:141` 只对 completed / expired 判定过期；`server.mjs:255` 逐张写结果，`server.mjs:264` 后续失败就把整个任务改为 failed。`server.mjs:181` 的清理跳过所有 failed 任务。中断恢复也改成 failed。`tests/ai-server.test.mjs:388` 明确验证了失败、中断记录的文件原样保留。
- 隔离复现：模拟供应商返回第一张合法 PNG、第二张坏图。任务变为 failed 后，将测试时钟推进 96 小时，再查询任务触发清理：`result-1.png` 仍存在，任务没有 expiresAt。这个文件没有对外媒体访问权限，但占据存储且没有清除期限。
- 上线前行动：区分成品保留期、失败半成品短期清理与最小审计记录保留。失败/中断时安全清理本站生成的中间文件；增加孤儿文件扫描和删除失败告警，继续保护用户上传原件。图片任务元数据目前永久保留完整 prompt，应将幂等所需的最小记录与业务内容保留规则分开。

### AI-07 · P2：过期清理依赖第一次 AI 请求，且无清理失败告警

- 证据：`preview.mjs:52` 懒初始化 AI handler；直到第一次 `/api/ai/*` 请求才会执行 `services/ai/server.mjs:203` 启动扫描与 `server.mjs:227` 定时器。`server.mjs:198` 删除失败和 `server.mjs:221` 坏记录都被静默忽略。`server.mjs:279` 的 status 只反映“是否填入密钥”，并非服务依赖健康状态。
- 影响：服务器停机跨过期限后重启，若尚未访问 AI，过期文件继续留在磁盘。权限错误、磁盘写满或损坏记录没有可监控告警。访问限制仍会在实际请求时生效，不能混同为过期公开可下载。
- 上线前行动：启动时主动初始化，或使用独立定时清理 worker；监控最后清理成功时间、待清理数量、失败次数、磁盘余量和任务滞留时间。日志记录任务 ID 和错误类别，避免输出密钥或整段商家资料。

### AI-08 · P2：Agent 历史属于浏览器，没有按用户隔离或跨设备保存

- 证据：`design/agent-chat.js:1` 使用固定 `store-ai-agent-conversations-v1` 键；`:26` 从 localStorage 直接读所有对话；`:57` 写回相同键，无账号维度或退出清理。
- 影响：换设备看不到历史；清理浏览器会丢失；接入登录后若不一起改，共用浏览器切换账号仍可能看到上一位使用者的文字。附件已经限制为页面内存，不应宣称能恢复历史附件。
- 上线前行动：如果要提供正式历史记录，按登录用户保存到服务端并定义保留期；本地缓存按账号命名并在退出/切换账号时清理。若第一版保留浏览器历史，需要明确展示它的限制，并仍解决换号串历史。

### AI-09 · P2：资产“加载更多”只分批展示，后端仍全量读取

- 证据：`services/ai/server.mjs:207` 启动读取所有任务；`:219` 全部常驻 Map；`:180` 每次清理扫整个 Map；`:278` 每个 AI 请求都等清理；`:299` completed=true 一次返回全部保留期作品。到期仅保留 tombstone，也一直留在 Map 中。
- 影响：前端一次显示 24 张不能降低接口响应体、后端启动成本或扫描成本。随着商家数与历史任务累计，所有 AI 请求都承担更大的扫描开销。
- 上线前行动：分页查询按商家、状态和完成时间建立索引；清理按到期索引分批运行；幂等 tombstone 留数据库最小记录而非永久装入所有进程内存。先用预计试用人数和日生成量做容量验证。

## 已经实现、上线时应保留的保护

- 模型密钥只在服务端使用；静态资源严格白名单。实际 `/.env.local` 返回 404；状态接口不返回密钥。
- 图片、文本、总请求体、供应商响应与下载大小有上限；不接受 assistant 携带图片；不会把供应商错误正文原样回传。
- 供应商图片 URL 只允许 HTTPS 公网地址，每次重定向重新校验并固定 DNS 解析，下载不携带模型凭据。
- 同一进程、包括重启加载后的同一 requestId 与内容能复用任务，冲突内容返回 409；任务记录先保存再提交模型，失败不自动重新付费。
- 成功作品从 completedAt 起精确计算 72 小时；过期不出现在成品列表，GET/HEAD 下载返回 410，未过期媒体使用 private/no-store。
- 清理只删除受管目录中的固定生成文件名，防止目录穿越与符号链接越界；到期立即隐藏，文件删除失败继续重试。

## 本轮证据汇总

| 验证 | 结果 | 代价/范围 |
|---|---|---|
| 匿名及任意 Cookie 查询图片 | 均 200，相同 5 个任务 | 只读现有本机服务，未输出文案正文 |
| 匿名任务详情与图片 HEAD | 200；详情含 prompt；媒体 image/png | 只读，不下载正文 |
| 非 localhost Host | 403 / HOST_REJECTED | 只读状态请求 |
| 根环境文件地址 | 404 | 未读取密钥 |
| 畸形 URL | 隔离子进程退出 1 / ERR_INVALID_URL | 独立子进程，无用户服务中断 |
| 失败半成品推进 96 小时 | 生成文件仍存在，任务无 expiresAt | 临时目录、模拟供应商 |
| 两实例同一 requestId | 两边 202，供应商 mock 调用 2 次 | 临时目录、无真实计费 |

以上是当前代码及本机行为的结论，不代表已完成生产 Linux 环境、公司 SSO、真实对象存储和高并发验收。上线阻断应先修复，再做双账号和服务器环境验收。
