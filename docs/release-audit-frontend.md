# 前端与整站发布入口审查（2026-09-30）

范围：`design/` 静态代码、前端调用关系、原图与草稿、展示素材、根目录启动与发布配置。未修改产品实现，未调用付费模型。外置浏览器实测、完整测试、安全和数字人后端审查由主审查分别汇总；本报告不把静态检查视为真实出片或生产部署验收。

## 结论

当前是可用的本机开发工作台。Agent 与原图生图已有真实调用链；数字人前端已经连接真实素材、任务与下载接口。AI 视频和混剪仍是编辑界面，没有生成服务。现有发布配置只能覆盖数字人原服务，不能直接部署新的完整网站。

若面向真实多商家开放，下面的 P0 项需先完成；如果第一版只发布 Agent 与 AI 图片，可以明确隐藏或标记尚未接入的模块，再推进生产部署。P0 表示阻断所承诺范围的正式开放，P1 表示上线前应解决，P2 表示可排入后续优化。

## 各模块实际状态

| 模块 | 已连接的行为 | 实际缺口 |

## 上线问题与证据

### P0-1：AI 视频和混剪并没有生成实现

- `design/app.js:125` 的通用 `generate()` 只打开“生成服务待接入”弹窗，没有发送生成请求。
- `design/workbench.js:51` 的视频按钮，包括 `director` 模式下的“生成宣传脚本”，最终都是 `data-action="generate"`；`design/app.js:156` 调到上述占位实现。
- `design/studios.js:224` 的 `studio-generate` 分支也只调用 `ctx.generate()`。
- `design/studios.js:58` 到 `design/studios.js:63` 的成片数量、自动字幕、背景音乐只是创作参数；本地排序不能产生合成视频。

影响：把整站作为四类生成工具发布时，用户完成上传和填写后仍无法出视频。需接入公司混剪能力及 AI 视频供应商，补齐任务、进度、失败重试、结果下载与资产保留；或首发隐藏未完成入口。上线验收必须覆盖真实出片，不能只验按钮可点。

### P0-2：新主站缺少生产登录闭环

- `design/app.js:88`、`design/index.html:6` 导航只有业务模块、资料和帮助，未提供登录/退出/当前账号入口。
- `design/digital-human.js:40` 对 401 只提示“重新登录数字人服务后重试”；`design/digital-human.js:323` 至 `346` 请求会话失败后只展示错误和重新加载，没有登录回跳。
- 资产页在 `design/generated-assets.js:97` 对 401/403 提示“需登录后查看”，同样没有明确的登录入口。

影响：生产环境启用现有数字人的鉴权后，未登录用户无法从主站完成登录并回到原操作。需要确定接公司 SSO 还是独立账号，使 Agent、图片、数字人、资产共用同一身份，并补会话失效、退出、回跳体验。不要将本机免登录表现当作上线可用性。

### P0-3：根目录只有开发启动，没有整站生产发布单元

- `package.json:6` 至 `15` 只有 `dev`、检查、测试及数字人子服务 build；没有整站生产启动或部署命令。
- `scripts/dev.mjs:37` 固定监听本机 5173，`scripts/dev.mjs:55` 启动 `next dev`，属于开发运行方式。
- `preview.mjs:45` 使用“development backend”限制，代理后端默认 3001；`preview.mjs:24` 固定写入 `x-forwarded-proto=http`。
- 现有 `services/digital-human/Dockerfile` 与 Compose 的构建上下文是数字人目录，未打包根目录的 `design/`、`preview.mjs`、`services/ai/`，不能承载这个新主站。

影响：把当前目录直接放到服务器不会形成完整的可运维生产服务；经 HTTPS 反向代理时也不能继续让后端误认为外部地址是 HTTP。需建立整站生产入口、HTTPS 反代、正确的可信代理头、配置与持久卷、进程守护/健康检查、日志、回滚；部署到公司现有服务器时还要规划端口、域名或子域，避免通用 `/api/*`、`/_next/*` 路径冲突。前端是原生静态 ES 模块，不强制要求新增前端构建框架；缺的是可复现的正式发布方式。

### P1-1：浏览器草稿/历史没有按账号隔离或同步

- `design/app.js:53`、`:60`、`:61` 使用固定 `store-ai-design-drafts`、`store-ai-design-profile` 键；`saveDraft()` 在 `:124` 主动把素材文件从草稿中去掉。
- `design/agent-chat.js:1`、`:54` 至 `58` 将全部会话写入固定 localStorage 键。
- `design/digital-human.js:3`、`:42` 至 `68` 使用固定数字人编辑器键；`:331` 至 `336` 换账号时清形象/任务列表和选择，却没有清口播 `script`，也没有给该草稿加用户命名空间。
- `design/workbench.js:6` 和 `design/home.js:59` 收藏同样使用固定浏览器键。

影响：换设备没有资料/草稿，清浏览器就丢失；接通多用户登录后，同一浏览器切账号仍会显示上一个账号的文字和商家资料。建议至少按用户/租户命名空间隔离并在退出时清内存，商家资料和重要草稿放入服务器数据库；如首发明确仅本地保存，也需做到账号隔离并保留清晰说明。

### P1-2：原图上传入口的约束不一致，失败发生得太晚

- 直接“上传原图”通过 `design/workbench.js:29` 至 `44` 调用 `validateImageRequest()`，正确限制 PNG/JPEG/WebP、单张 8 MB、合计 24 MB、最多 9 张。
- “从素材库选”在 `design/workbench.js:66` 进入通用 `picker('image')`，但 `design/app.js:118` 使用 `accept="image/*"`，`:120` 只限制单文件 100 MB。
- `design/image-generation.js:12` 至 `24` 直到生成校验才拒绝这些不支持的格式/大小。

影响：从素材库选择 GIF、SVG 或超过 8 MB 的图片会先显示选中，随后生成按钮不可用；与直接上传表现不同。应让所有进入生图的入口采用同一校验，并在选择阶段明确原因。该问题不会绕过服务端校验，但会增加用户操作和困惑。

### P1-3：素材原图体积大，开发服务器对静态资源禁用缓存

- 本地只读统计：`design/media` 共 39 张图片，总计 **46.38 MiB**；首页展示库首批 12 张合计 **25.55 MiB**，6 张场景封面合计 **12.40 MiB**。
- `design/material-catalog.js:88`、`design/home.js:13` 至 `18` 直接引用这些 PNG 原图；`design/home.js:98` 和 `:134` 虽然采用 `loading="lazy"`，但没有缩略图尺寸版本或 `srcset`。
- `preview.mjs:63` 每次读取完整文件，`:64` 对所有静态资源返回 `Cache-Control: no-store`。

影响：浏览完首批素材和场景封面就可能下载约 38 MiB，手机网络和多人访问时带宽开销明显；这是文件大小计算，不是浏览器首屏实测流量，懒加载会推迟部分下载。上线前制作 WebP/AVIF 缩略图与不同尺寸、静态资源版本缓存/CDN；生成私有成品仍须维持鉴权和不缓存规则，不能一并改成公开长缓存。

### P1-4：数字人依赖原后端完整运行环境，不能当纯前端部署

- `design/digital-human-api.js:1` 所有数字人调用从同源 `/api` 发起；`preview.mjs:53` 至 `57` 将这些请求及 `/_next`、登录路径转给 3001 服务。
- `services/digital-human/Dockerfile:27` 至 `35` 安装 ffmpeg/ffprobe 与浏览器依赖，`:46` 安装 Remotion 浏览器；package build 还会先生成 motion bundle。
- `README.md:45` 至 `53` 已说明独立账号需 PostgreSQL，真实出片需配音/对口型供应商和外部可访问媒体地址；当前尚未完成真实成片和生产部署验证。

上线前需用目标 Linux 容器/服务器做一次干净构建、字体与中文渲染、上传/转码/配音/口型/下载/72 小时过期的端到端验收。可以共用公司原能力，但必须先明确接口身份、路径及存储的实际配置，不能仅复制前端页面。

### P2-1：资产目前是一次读取全集，后续需要服务端分页

- `design/generated-assets.js:109` 并行请求最近 3 天全部图片任务和数字人任务。
- `design/generated-assets.js:72` 用 `slice(0, state.limit)` 截取卡片，“加载更多”只是增加本地展示数量。

首批小规模可用；业务量上来时三天仍可能有大量记录，需按用户分页、缩略图及列表性能预算。若先补多用户隔离后人均生成量很小，可以后续再做。

### P1-5：当前没有可复现、可回滚的项目版本

本次只读 `git status --short` 显示根配置、前端、后端、文档、测试均为 untracked；主审查确认本地尚无初次 commit。`README.md:76` 也说明远程仓库仍为空。上线前需要完成密钥/数据排除检查、代码版本归档、测试门禁、部署版本标记及回滚方案。当前审查不主动提交或推送代码。

## 预设必填项复核

已通过，无产品缺陷。主审查外置浏览器复核发现首次使用测试工具 `fill('')` 后，DOM 实际值仍为原标题，并未真正清空。改用全选和 Backspace 删除，确认 DOM 值为空后点击保存，页面正确显示“请填写主标题”，弹窗保持打开。代码也一致：`design/image-presets.js:85` 对空白标题报错，`:95` 在生成提示词前再次校验；`design/image-preset-ui.js:120` 至 `128` 保存时展示错误并终止。两个实际预设的空标题纯函数检查均正确拒绝，未发现静默回退默认值。

## 素材来源审查边界

`design/media/SOURCES.md:3` 至 `22` 对最早一批摄影仅记录 Unsplash 图片编号和许可入口，后续工厂摄影在 `:25` 起有摄影者/来源页；AI 示例有独立生成记录。`design/material-catalog.js`、`design/home.js:98` 明确标注摄影参考/AI 风格示例，方向复用不自动当作用户原图。

本次没有发现可据此认定的侵权；也没有重新在线核验许可，因此不作“所有素材已完成商业授权审核”的结论。公开发布前可补齐最早那批照片的来源页、人物/品牌使用条件存档，继续保留“示例”标签，并让用户使用自己的真实素材。现有来源记录比没有来源的占位图库更清楚，无需无证据地把整库认定为不能商用。

## 响应式与交互验证边界

现有 CSS 包含桌面、平板、760/440 px 断点，表单多数有 label/aria，模态框使用原生 dialog，并有 reduced-motion 样式。没有因为静态代码里有断点就宣称手机验收完成。应在实际 390/430 px、平板、1366/1920 桌面及键盘操作下验证：上传与长文案、模态溢出、软键盘、后台任务恢复、窄屏预览、下载文件名、登录回跳。主审查的浏览器结果优先于这一静态判断。

## 建议的上线验收顺序

1. 确认首发范围：未完成的 AI 视频和混剪补接口，或者明确延后并移出可生成入口。
2. 接公司统一身份，完成所有接口的用户隔离，同时处理前端草稿/历史的账号隔离。
3. 建立整站生产发布及目标服务器配置，验证不冲突的域名、端口、反向代理和持久化数据目录。
4. 用两名测试用户覆盖真实生成、失败、刷新、会话失效、下载、跨用户不可见、72 小时清理和源素材保留。
5. 压缩展示素材、统一上传提示，再做桌面/手机与网络异常验收，最后小范围灰度。
