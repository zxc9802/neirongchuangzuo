# 起芽内容创作 · 实体生意宣传工作台

以茂隆掌柜 AI 的已核实页面交互为参考，面向实体门店、工厂、生产加工与批发企业设计 AI 图片、AI 视频、AI 混剪与数字人。明确排除画布页面和功能。

当前包含全站工作台 `design/`、Agent 与图片模型服务 `services/ai/`，以及导入同事项目的数字人后端 `services/digital-human/`。数字人页面保留本站蓝白风格，采用 Oumomo 式上下布局：上方集中生成，下方按需加载素材与作品卡片，通过同源代理接入后端；同事项目自带的制作台保留用于联调。

Agent 对话已接入 OpenLux 的 `gpt-6-luna`，通用图片已接入 `gpt-image-2.5-sunburst-c`。AI 图片新增默认「餐饮小红书」模式：实拍上传 → 自动分析推荐 → 选择方向 → 常规美化/封面与文案 → 审核 → 下载发布包。餐饮照片不通过生成模型重画，识图和文案使用 Luna；资料和正式额度账本按账号保存在 PostgreSQL，任务文字保留 30 天，原图与成品保留 3 天。具体范围、接口和部署交接见 [餐饮小红书实施与部署](docs/餐饮小红书实施与部署.md)。当前不支持链接导入或 PDF 等文档上传。AI 混剪已接入网页本地素材库：文件夹扫描、后台增量向量化、文案匹配和服务器制作，部署配置见 [AI 混剪网页素材库](docs/AI混剪网页素材库.md)。AI 视频仍未接入生成服务。5173 的数字人模块支持真实上传、素材管理和任务接口，但配音、对口型及公共媒体访问仍需独立配置。

首页与工作台共用的展示库包含摄影参考和 AI 风格示例，用于展示创作方向，不是用户自己的素材或生成结果。网站已部署至 https://nrcz.qycm.top/，主分支推送会触发 Zeabur 自动部署；已有全站登录、注册和账号隔离。新注册需要 6 位数字与大写字母组合的一次性邀请码，管理方式见 [邀请码管理](docs/邀请码管理.md)。内部账号从原库只读验证，新注册账号写入独立数据库，配置及边界见 [双库登录](docs/双库登录.md)。原有模型能力、配置与验证边界见 [模型接入](docs/模型接入.md)。

生产启动使用 `npm start`，主站监听 `0.0.0.0:$PORT`，数字人后端由启动脚本一并启动。Zeabur 使用仓库根目录的 Dockerfile，配置方法与持久化目录见 [Zeabur 部署](docs/Zeabur部署.md)。

## 本地打开

安装 Node.js 20.19+（Docker 使用 Node.js 24），首次先按下文准备数字人依赖和本地配置，然后在仓库根目录执行：

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173；数字人入口为 http://127.0.0.1:5173/#avatar。该命令由 `scripts/dev.mjs` 启动工作台与数字人后端；如果 3001 已有可用的数字人服务，会复用它。

`npm run dev:design` 启动工作台、Agent / 图片模型接口和数字人同源代理，不会启动数字人后端。启用独立账号后，登录与工作台访问也需要数字人后端运行。

## Agent 与 AI 图片配置

首次将仓库根目录的 `.env.example` 复制为 `.env.local`，填写 `OPENLUX_API_KEY`；已有配置不要覆盖。默认模型为 `OPENLUX_CHAT_MODEL=gpt-6-luna` 和 `OPENLUX_IMAGE_MODEL=gpt-image-2.5-sunburst-c`，修改配置后重启工作台。根目录 `.env.local` 已被 Git 忽略，密钥仅由服务端读取，不能写入前端、文档或提交记录。

Agent 支持文字多轮对话和参考图片。通用图片支持上传 PNG、JPEG、WebP 原图，单张最多 8MB，最多 9 张、合计最多 24MB；创作要求最多 1000 字。支持单张图片、统一风格套图和同主题多风格，页面默认统一风格 4 张，套图可选 2、3、4 张，每张独立生成。套图先预留全部所需图片调用额度，再逐张调用模型；额度不足不会开始。任务可查询、刷新恢复、预览与下载，失败或响应不确定时不会自动重复调用模型。部分成功时保留成功图片，明确提示未完成数量。返回图片的实际像素可能与请求值不同，页面的比例设置不代表固定分辨率承诺。

原有模型调用经过本站 `/api/ai/` 接口；通用图片原图只在当前请求中处理，成品和任务记录保存至 `.data/ai/`。餐饮模式经 `/api/restaurant/`，原图与成品另按 3 天期限保存，历史任务文字保留 30 天；餐饮门店资料服务端长期保存。运行数据目录均已被 Git 忽略。原有接口见 [模型接入](docs/模型接入.md)。

全站默认每日图片 20 次、Luna 调用 100 次（Agent 与餐饮共用），每分钟共 10 次，北京时间零点重置；可以通过 `.env.local` 的 `AI_IMAGE_DAILY_LIMIT`、`AI_CHAT_DAILY_LIMIT`、`AI_REQUESTS_PER_MINUTE` 调整，0 表示禁止调用。供应商请求发出后即计次，失败或超时也不会自动返还，这不是金额账单。餐饮另按每账号每日成功交付 20 套控制正式额度，分析、失败和自动重试不扣正式额度。服务使用独占运行锁，只允许一个实例。

服务启动后自动清理 72 小时前的生成结果，全失败任务的半成品立即清理，套图部分成功的可用成品继续按 72 小时保留，清理失败会记录告警并重试；`GET /api/ai/usage` 可查看额度和清理状态。关闭时等待已发出的任务完成再释放运行锁。部署与运行说明见 [本轮修复验收](docs/调用控制与清理验收-2026-09-30.md)。

## 数字人开发服务

在本仓库根目录执行：

```sh
npm run setup:digital-human
```

首次将 `services/digital-human/.env.example` 复制为该目录下的 `.env.local`；已有配置时不要覆盖。根目录及数字人服务均设置 `AUTH_MODE=standalone`，并按 [双库登录](docs/双库登录.md) 配置账号数据库。然后启动：

```sh
npm run dev:digital-human
```

单独联调可打开 http://127.0.0.1:3001。日常使用从 5173 的数字人入口进入。服务仅绑定本机地址，仅本机且未配置 SSO 的开发模式可无需登录；正式使用独立账号需设置 `AUTH_MODE=standalone` 并配置 PostgreSQL，生产环境保留原有鉴权限制。本地配置使用 `AUTH_PUBLIC_URL=http://127.0.0.1:5173`、`AUTH_DESKTOP_URL=http://127.0.0.1:3001`。

数字人素材是人物口播视频。真实出片需要自己的配音接口和一种对口型接口，以及外部模型可访问的媒体地址或对象存储。原页面默认引擎 `b` 对应 fal/VEED；`a` 对应 OpenLux/PixVerse，`c` 对应 HeyGen。默认音色未配置参考音频时需自行上传声音。密钥通过服务端环境变量配置，设置页不提供密钥录入。

前端流程、页面文件和真实接口见 [数字人前端对接](docs/数字人前端对接.md)；来源及本地调整见 [UPSTREAM](services/digital-human/UPSTREAM.md)。新页面为 `design/digital-human.js` 和 `design/digital-human.css`，接口适配层为 `design/digital-human-api.js`；`preview.mjs` 将数字人的接口、素材和结果请求流式转发至 3001，本站 `/api/ai/` 单独处理。

可用检查命令：`npm run check`、`npm test`、`npm run check:digital-human`、`npm run test:digital-human`、`npm run build:digital-human`。数字人已执行的检查、页面联调及未完成项记录在 [数字人接入验收](docs/数字人接入验收.md)。PostgreSQL 双库账号流程已完成集成验证；数字人供应商真实成片尚未验收。

`/api/digital-human/status` 只报告服务配置是否齐备；显示就绪不代表供应商账号、额度或真实生成已实测可用。

## 本轮迭代

- **生成资产**：侧栏资产集中展示本站生成成功的图片、数字人成片和配音，按完成时间保留 72 小时，支持预览、下载和到期自动清理。上传原图、形象和声音不受此规则影响。详见 [生成资产与保留期](docs/生成资产与保留期.md)。
- **生图预设**：AI 图片新增“工厂宣传海报”和“小红书推销封面”。上传原图后直接点选风格即可生成；默认文案、比例与画质自动带入。“修改文案”是选填，完整提示词与参数收在“更多设置”。保留已选原图，支持撤销切换、草稿保存与继续调整；首页及对应素材卡也可直接选用风格。使用与新增预设的维护方式见 [生图预设](docs/生图预设.md)。
- **行业宣传流程**：选择行业、用途与平台 → 填写必要事实、添加真实素材 → 检查文案、口播稿、画面顺序和素材清单 → 带入四个创作模块。支持下载文字方案；方案随草稿保存。当前使用明确的行业模板整理方案，不冒充模型生成。
- **八类主营用户**：餐饮咖啡、美业、零售、健身、工厂直销、生产代工、工业加工、批发供货。工厂按合作方式分别收集材料、定制、起订、打样、工艺、规格、交期和发货条件；套餐、代金券和单品活动使用不同表单。
- **首页与展示库**：行业、用途与平台选择，六类宣传场景；共享 32 个素材方向，14 张 AI 行业图片优先展示，覆盖餐饮、美业、零售、健身、家具、代工、工业加工与批发，包含“好工艺，看细节”工厂宣传海报及“找加工厂，这4点先说清”小红书推销封面。六个场景另有独立 AI 封面，不在素材列表重复使用。首页首批展示 12 项，每次加载更多 6 项，支持行业筛选、收藏与方向复用；摄影参考、AI 风格示例及既有 AI 形象参考分别标注。
- **Agent 对话**：入口位于首页与 AI 图片之间；独立历史侧栏、会话输入与参考图片，已接入 Luna 的真实回复，可将需求带入四个创作模块。每次发送最近最多 20 条消息、合计最多 32000 字；文字历史保存在当前浏览器，参考图片只在当前页面内存保留。
- **餐饮小红书**：上方门店资料、照片、方向选择和发布包，下方历史任务按需加载；只有成功交付的餐饮成品进入侧栏资产页。
- **通用图片 / AI 视频**：保留左侧编辑、中间预览、右侧草稿队列；有行业方案时优先显示本次文案与画面顺序，仍可浏览共享的摄影参考、AI 风格示例、自己的素材与收藏。AI 图片已接通原图编辑、真实任务记录和作品下载；AI 视频暂未接模型。
- **AI 混剪**：选择本地素材文件夹，左侧小型进度区显示扫描和向量化；输入宣传文案，使用当前账号目录中的向量匹配镜头，按需临时传片并在服务器制作，支持预览和下载。
- **数字人**：上方选择视频形象、声音并填写文案，生成参数折叠收纳；下方按“全部 / 视频形象 / 生成作品”展示卡片，滚动至底部逐页加载。保留音色管理、任务进度、成片下载和可恢复任务操作。形象输入为口播视频，不提供后端未实现的背景、字幕等设置。
- **共用能力**：按类型筛选与文件名搜索素材、商家资料、草稿保存与恢复。关闭行业表单不覆盖原创作；兼容素材可随制作类型切换；不同商家或行业不会沿用上一个商家的活动与采购条件。画布页面和功能完全排除。

数字人上传的形象视频和参考声音由后端持久化保存，刷新后可再次加载；任务状态和结果以服务端为准。通用图片的成品与任务保存在 `.data/ai/`；通用图片原图、Agent 参考图及 AI 视频工作台素材文件只留在当前页面内存中，刷新需重新选择。原有模式的文案、参数、商家资料、Agent 文字历史及收藏保存在当前浏览器 localStorage；餐饮模式的资料、任务和额度按上文在服务端保存。未接入服务的模块不会展示虚假的生成成功或积分消耗。混剪原视频留在电脑，目录授权有效时可自动恢复并增量索引；兼容目录输入模式需要重新选择。制作期间需要保持网页连接。

数字人展示区通过 `/api/digital-human/library` 按游标分页，默认每次 12 条，支持加载失败重试与手动加载更多；原有完整素材和任务列表接口继续保留。

选择展示库里的创作方向，只带入行业、用途及表达要求；参考图片不会进入“我的素材”，也不会被当成商家自己的店铺、产品、服务案例或工厂实拍。继续创作时需选用自己的原图或视频。图片来源和生成记录见 [素材来源](design/media/SOURCES.md)：原 18 张通过内置 `image_gen` 独立生成（12 张行业素材、6 张场景封面），另有 2 张通过网站 Image 2.5 编辑接口生成的工厂宣传图，分别为品牌海报和小红书推销封面。

详细范围、参考站核实情况、四模块流程和早期状态设计见 [产品设计](docs/产品设计.md)。旧设计与验收报告保留各自当时的实施状态；Agent 与 AI 图片的最新状态以 [模型接入](docs/模型接入.md) 为准。

仓库不包含密钥、依赖、运行数据或用户上传文件。首次启动需自行准备本地配置和数字人依赖。
