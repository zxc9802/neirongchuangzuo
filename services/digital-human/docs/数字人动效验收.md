# 数字人动效模块 · 本地验收

日期：2026-09-14。新增独立入口 `/motion`，使用 Remotion；未修改数字人口型生成链路，未推送或部署线上。

## 已实现

上传最终剪辑版 → 自动字幕 → 按相邻一到两句整理总结卡 → 校对文字、时间和重点词 → Remotion 预览/渲染 → 下载 MP4。

顶部固定黄字纹理、双层描边标题和白字副标题。人物画面可选择铺满或保留完整画面；字幕位于人物下方。底部绿色金边卡片按口播切换，含标题、最多两行总结、逐行入场和黄色重点词划线。

任务、权限和存储与数字人生成任务分开，复用现有授权上传和私有媒体服务。支持 SRT、保存校对、重试、刷新后从最近任务恢复。

## 实际测试中修复的问题

1. ASR 个别汉字起止时间相同，最初会中止整条任务；现已保留这些字并归入相邻口播时间。
2. ASR 逐字结果遗漏百分号；优先采用含标点和符号的分句结果，保留原始时间戳。
3. 模型曾把整段视频合成一张卡；现由程序固定相邻一到两句的分组，模型只能总结对应分组，不能合并或遗漏。
4. 可选高亮词若未出现在模型总结正文，自动取消该高亮；手动填写不存在的高亮词仍会提示修正。
5. 明确采用 H.264、YUV420P、BT.709 输出，原声只做复制封装。

## 上传按钮无响应修复

用户操作时，视频上传接口已成功，创建动效任务却连续返回 429。原因是新模块无条件调用外部账号限额，本地验收的 6 次整理/渲染操作占满了 `motion:local` 的小时额度；错误提示又位于页面顶部，点击处看不到结果。

现按现有系统的服务端账号分类，仅对外部账号计入小时额度；本地、内部和管理员任务仍保留每账号单任务与全局并发保护。没有删除或重置实际限额台账。上传状态和错误改为显示在提交按钮旁，错误出现时滚动到提示，处理中按钮明确显示状态。

回归测试先复现本地创建返回 `429` 而非 `202`，修复后验证本地、内部、管理员的创建和渲染成功，外部账号仍返回 429；169 项测试及 TypeScript 检查通过。在用户原页面恢复原视频与双行标题后实际点击，创建接口返回 202，16 秒视频完成整理，产出 7 条字幕、4 张总结卡，状态为「待生成」。项目 ID：`motion_327ea42d-35ea-4e1a-81a7-7ca26f638d94`。

## 自定义人物画面裁剪

「最终剪辑版 → 人物画面 → 手动裁剪」提供固定比例画框、鼠标/触摸拖动、100%–300% 缩放、方向键微调、重置，以及按视频进度检查画面。裁剪参数 `x/y/zoom` 经接口验证后随任务保存，编辑器、Remotion Player 和成片共用变换；旧任务默认居中。

浏览器使用原 20 秒验收任务进行实际拖动，保存了 `x=0.23483503289195562, y=0.15061687957200598, zoom=1.2`。刷新并重新打开后位置恢复，视频进度可跳到第 8 秒，重新渲染的 MP4 第 8 秒画面与裁剪框一致，原声及全片解码校验通过。输出同目录 `evidence.json` 包含实际裁剪参数。

补齐本地私有媒体的 Range 响应，解决检查后半段时跳回开头的问题：实际请求 `bytes=100-109` 返回 206 和 10 字节，边界、尾部区间、HEAD 及私有路径回归通过。175 项测试、TypeScript 检查、Remotion 模板打包通过。

## 运行边界

- 裁剪是整条视频使用同一范围，不包含分镜切换或人物自动跟踪。

- Codex 内置浏览器播放页曾崩溃，标准编码复测仍不稳定；当前播放验收以 Chrome 为准。
- 当前验证是本地开发环境；未验证线上 SSO/COS、长视频满负载、Docker 实际启动或多副本部署。
- Dockerfile 已补充 Chromium 依赖、中文字体、Remotion 浏览器安装及模板打包产物。
- 语音/总结默认使用已有 302 配置，可通过 README 中的独立动效环境变量覆盖。
- 保留现有单服务后台任务模式；服务重启中的任务明确标记为失败并允许重试。
